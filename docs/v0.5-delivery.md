# cub-scout v0.5 Delivery Execution Plan

This document defines how Codex and Claude collaborate to deliver cub-scout v0.5.

The operating model prioritizes correctness, visibility, and scope discipline.

---

## Roles & Responsibilities

### Claude — Repository Executor

Claude is responsible for:
- Updating GitHub (code, docs, issues, PRs)
- Implementing scoped changes
- Writing tests where required
- Updating documentation to match reality
- Following CLAUDE.md and the v0.5 addendum

Claude MUST NOT:
- Introduce speculative features
- Expand scope without explicit instruction
- Infer ownership or intent not backed by data
- Modify core behavior without tests or documentation

Claude acts only on **explicit, written tasks**.

---

### Codex — Delivery Lead & Arbiter

Codex is responsible for:
- Defining v0.5 scope and priorities
- Breaking work into ordered, reviewable tasks
- Approving waivers
- Resolving tradeoffs between correctness, UX, and scope
- Deciding go / no-go for release

Codex is the final authority on:
- What ships in v0.5
- What is deferred
- Whether a change violates core principles

---

## Source of Truth

The following documents form the delivery contract:

1. `CLAUDE.md` (including v0.5 addendum)
2. v0.5 delivery checklist (maintained by Codex)
3. GitHub issues explicitly labeled for v0.5

If there is a conflict, Codex resolves it explicitly.

---

## Task Structure

All work for v0.5 MUST be expressed as a task with:

- Clear intent ("what problem is being solved")
- Explicit success criteria
- Defined failure modes
- Scope boundaries ("what this task will not do")

Claude executes tasks exactly as written.

If ambiguity exists, Claude must stop and ask Codex.

---

## Change Categories

### Allowed Without Escalation
- Bug fixes
- Documentation clarifications
- Test additions
- UX polish that does not alter semantics

### Requires Codex Approval
- Ownership logic changes
- New interpretations of controller behavior
- Changes to CLI contracts
- Waivers of testing or completeness expectations

---

## Waiver Handling

When a waiver is needed:

1. Claude flags the need explicitly.
2. Codex approves or rejects the waiver.
3. The waiver is documented in:
   - Code comments and/or
   - GitHub issue
4. A follow-up issue is created.

No implicit waivers are allowed.

---

## Review & Validation Loop

For each meaningful change:

1. Claude implements the change.
2. Claude documents assumptions and limitations.
3. Codex reviews for:
   - Correctness
   - Scope adherence
   - Principle alignment
4. Only then is the change merged.

---

## Freeze & Release

At v0.5 freeze:

- No new features are accepted.
- Only:
  - Bug fixes
  - Crash fixes
  - Documentation corrections

Release proceeds only if:
- Known limitations are documented
- No unsafe ambiguity remains
- Trustworthiness bar is met

---

## Guiding Principle

cub-scout v0.5 must earn trust.

When in doubt:
- Prefer less behavior over wrong behavior
- Prefer explicit unknowns over silent assumptions
- Prefer clarity over cleverness
