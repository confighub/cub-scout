# cub-scout v0.5 Delivery Checklist

This checklist defines the **non-negotiable exit criteria** for the cub-scout v0.5
release.

v0.5 ships only if **all applicable items are satisfied or explicitly waived**.

---

## 1. Ownership & Provenance (Core)

- [ ] Flux ownership detection is correct and reproducible
- [ ] Argo CD ownership detection is correct and reproducible
- [ ] Helm ownership detection is correct and reproducible
- [ ] Manual / kubectl-applied resources are detected conservatively
- [ ] Ownership precedence rules are documented
- [ ] Ambiguous ownership is surfaced as unknown, not guessed
- [ ] No false orphan or unmanaged claims observed in test clusters

**Verification**
- [ ] Tested against at least one Flux-managed cluster
- [ ] Tested against at least one Argo CD–managed cluster
- [ ] Ownership claims match ground truth

---

## 2. Failure & Health Modeling

- [ ] Failed reconciliation states are detected correctly
- [ ] Suspended / stalled resources are represented accurately
- [ ] Root controller for failures is identifiable
- [ ] Failure explanations distinguish between:
  - [ ] Input (Git)
  - [ ] Controller behavior
  - [ ] Runtime / cluster state
- [ ] Failure output suggests the correct class of next action
      (wait / fix Git / intervene)

---

## 3. TUI Stability & UX

- [ ] No panics or crashes on empty clusters
- [ ] No panics or crashes on malformed or partial clusters
- [ ] Navigation is predictable and consistent
- [ ] Keybindings are frozen and documented
- [ ] Help / guidance is discoverable
- [ ] Errors are visible and understandable in the UI

---

## 4. CLI Contract

- [ ] `cub-scout map` behavior is stable
- [ ] `cub-scout trace <resource>` behavior is stable
- [ ] Any additional commands are documented and justified
- [ ] Machine-readable output (`--json`) works where documented
- [ ] Error messages are actionable

---

## 5. Tests & Safety

- [ ] Ownership logic has deterministic tests
- [ ] Failure classification logic has deterministic tests
- [ ] UI logic has been exercised against real clusters
- [ ] Any missing tests are covered by explicit waivers
- [ ] No known unsafe failure modes remain

---

## 6. Documentation

- [ ] "What cub-scout is / is not" is accurate
- [ ] 10-minute quickstart works as written
- [ ] One realistic walkthrough is complete
- [ ] Known limitations are documented
- [ ] Docs do not over-promise behavior

---

## 7. Scope Discipline

- [ ] No connected-mode dependency required
- [ ] No multi-cluster features included
- [ ] No speculative controller support
- [ ] All included features align with v0.5 priorities

---

## 8. Waivers (If Any)

For each waiver:
- [ ] Limitation is documented
- [ ] Failure mode is safe
- [ ] Follow-up issue exists
- [ ] Waiver is approved by Codex

---

## 9. Release Readiness

- [ ] No known crashers remain
- [ ] Known limitations are visible to users
- [ ] Tool can be recommended to another operator with clear caveats
- [ ] v0.5 release notes are written
- [ ] Go / No-Go decision recorded

---

## Final Decision

- [ ] **GO** — v0.5 meets trust and utility bar
- [ ] **NO-GO** — unresolved issues remain
