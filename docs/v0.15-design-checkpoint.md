# v0.15 Design Checkpoint

**Status:** APPROVED
**Date:** 2026-02-04
**Scope:** Multi-bundle replay and time-series reasoning

---

## Non-negotiable Axioms

1. **A bundle is immutable** and self-contained (v1 stays valid)
2. **Time-series meaning only exists when explicitly constructed** (no "latest", no implicit ordering)
3. **New meaning = new JSON schema** (diffs/timeline outputs are new facts)
4. **ASCII remains f(JSON)+g** for any new outputs

---

## 1) Bundle Catalog Schema

### Decision: Directory-based catalog with explicit manifest file

**Layout:**
```
catalog/
  catalog.json
  bundles/
    <bundle-id-1>/...
    <bundle-id-2>/...
```

### catalog.json Schema (`catalog.v1`)

```json
{
  "schema_version": "catalog.v1",
  "bundles": [
    {
      "id": "incident-123-before",
      "path": "bundles/incident-123-before",
      "created_at": "2024-01-15T10:00:00Z",
      "digest": "sha256:abc123...",
      "scope": {
        "cluster": "prod-east",
        "namespace": "api",
        "target": "Deployment/api"
      },
      "labels": {
        "source": "ci",
        "ticket": "INC-123"
      },
      "sequence": 1
    }
  ]
}
```

**Fields:**
| Field | Required | Description |
|-------|----------|-------------|
| `id` | Yes | Stable identifier |
| `path` | Yes | Relative path to bundle directory |
| `created_at` | Yes | Copied from bundle metadata (validated) |
| `digest` | No | SHA256 of bundle contents |
| `scope` | Recommended | Enables "same thing" grouping |
| `labels` | No | Arbitrary key/value metadata |
| `sequence` | No | Explicit ordering integer |

**Rules:**
- Catalog ordering is authoritative (not inferred from directory listing)
- No database in v0.15 (future backend interface if needed)

## 2) Temporal Join Semantics

### Decision: Primary key = `object_id` with explicit join modes

**Join Modes (CLI flag + JSON field):**

| Mode | Description |
|------|-------------|
| `--join object_id` | Default: join on object_id |
| `--join composite` | Join on (kind, namespace, name) |
| `--join none` | No joins; independent snapshots |

**Collision/Missing Rules:**
- Missing join key → `unjoinable` status with reason code
- Multiple matches → `ambiguous` status, no narrative claiming continuity

**Principle:** Continuity is a declared operation, not inference.

## 3) Comparison Output Schema

### Decision: New top-level schemas for diff and timeline

### A. Pairwise Diff (`bundle-diff.v1`)

```json
{
  "schema_version": "bundle-diff.v1",
  "from": { "id": "...", "created_at": "...", "digest": "..." },
  "to": { "id": "...", "created_at": "...", "digest": "..." },
  "scope": { "cluster": "...", "namespace": "...", "target": "..." },
  "join_mode": "object_id",
  "summary": {
    "added": 2,
    "removed": 1,
    "changed": 3,
    "unchanged": 10,
    "ambiguous": 0,
    "unjoinable": 1
  },
  "objects": [
    {
      "identity": { "object_id": "Deployment:prod/api" },
      "status": "changed",
      "sections": {
        "drift": { "before": 2, "after": 5, "delta": 3 },
        "events": { "before": 10, "after": 15, "delta": 5 }
      }
    }
  ]
}
```

### B. Timeline (`bundle-timeline.v1`)

```json
{
  "schema_version": "bundle-timeline.v1",
  "catalog": { "id": "incident-123", "version": "catalog.v1" },
  "ordering": { "mode": "created_at", "tie_break": "id" },
  "join_mode": "object_id",
  "series": [
    {
      "identity": { "object_id": "Deployment:prod/api" },
      "points": [
        { "bundle_id": "before", "drift_count": 2, "event_count": 10 },
        { "bundle_id": "after", "drift_count": 5, "event_count": 15 },
        { "bundle_id": "resolved", "drift_count": 0, "event_count": 3 }
      ]
    }
  ]
}
```

**Rule:** Diffs are new facts in new schemas (never smuggled into existing bundle files).

## 4) Ordering Guarantees

### Decision: Explicit ordering modes, never filesystem-based

**Supported Modes:**

| Mode | Description |
|------|-------------|
| `--order manifest` | Default: order as listed in catalog.json |
| `--order created_at` | Sort by metadata.created_at, tie-break by id |
| `--order sequence` | Sort by catalog sequence field, tie-break by id |
| `--order input` | Preserve CLI argument order |

**Hard Prohibitions:**
- No directory listing order
- No "latest"
- No wall-clock "now"

**Tie-break Rule:** If two bundles have identical sort keys, tie-break by `id` (lexicographic).

```bash
# Catalog management
cub-scout catalog init <dir>

cub-scout bundle diff <bundleA> <bundleB> [--join ...] [--format json|ascii]
cub-scout bundle timeline <catalog> [--join ...] [--order ...] [--format json|ascii]
```
