# v0.14 JSON Schema Specification

**Status:** Implemented (v0.14.0), updated for v0.14.4
**Purpose:** Lock semantic meaning for sharable outputs
**Principle:** JSON is the complete truth; ASCII/MD are projections (see docs/semantic-contract.md)

---

## Design Constraints

1. **Lossless** — JSON contains ALL data; display limits are metadata only
2. **Deterministic** — Same input = same JSON (no timestamps, stable ordering)
3. **No UI concepts** — No cursor, panels, colors, widths
4. **Structured evidence** — Relationships proven with typed key/value pairs

---

## Determinism Rules (LOCKED)

**No time-derived fields by default:**
- No `timestamp`
- No `age`
- No `lastSeen`

If time is needed later: opt-in via `--include-time` flag (non-golden output).

**Ordering (applied everywhere):**
- Owner groups: canonical order `[Flux, ArgoCD, Helm, ConfigHub, Native]`
- Resources: sorted by `(namespace, kind, name)` lexicographically
- Trace chains: ordered by relationship (source → deployer → workload)

Note: Crossplane is not yet a first-class owner category. Crossplane-managed resources currently fall to "Native" until Crossplane detection is added to the canonical ownership model.

## Common Types

### ResourceID (canonical identity for joins)

```json
{
  "kind": "Deployment",
  "namespace": "web",
  "name": "frontend"
}
```

### Owner

```json
{
  "type": "Flux | ArgoCD | Helm | ConfigHub | Native",
  "ref": "ResourceID | null"
}
```

### Evidence (structured proof of relationship)

```json
{
  "type": "label | annotation | ownerRef | field | inventory",
  "key": "kustomize.toolkit.fluxcd.io/name",
  "value": "web-apps",
  "path": "metadata.labels"
}
```

Evidence types:
- `label` — Kubernetes label proving ownership
- `annotation` — Kubernetes annotation proving ownership
- `ownerRef` — metadata.ownerReferences entry
- `field` — spec/status field reference (e.g., spec.sourceRef)
- `inventory` — presence in GitOps inventory/resources list

### DisplayMeta (for ASCII/TUI rendering parity)

```json
{
  "maxItems": 3,
  "totalItems": 10
}
```

**Rule:** JSON `items` always contains ALL items. `displayMeta` indicates what ASCII would show.

## 1. Tree Schema

**Command:** `cub-scout tree ownership [--format json]`

**Purpose:** What exists, grouped by owner

```json
{
  "command": "tree",
  "subtype": "ownership",
  "context": {
    "cluster": "prod-us-east",
    "namespace": null,
    "filters": {
      "owner": null,
      "maxItems": 3
    }
  },
  "groups": [
    {
      "owner": "Flux",
      "displayMeta": {
        "maxItems": 3,
        "totalItems": 10
      },
      "items": [
        {
          "id": {
            "kind": "Deployment",
            "namespace": "api",
            "name": "backend"
          },
          "ownerRef": {
            "kind": "Kustomization",
            "namespace": "flux-system",
            "name": "api-apps"
          }
        },
        {
          "id": {
            "kind": "Deployment",
            "namespace": "web",
            "name": "frontend"
          },
          "ownerRef": {
            "kind": "Kustomization",
            "namespace": "flux-system",
            "name": "web-apps"
          }
        }
      ]
    },
    {
      "owner": "Native",
      "displayMeta": {
        "maxItems": 3,
        "totalItems": 2
      },
      "items": [
        {
          "id": {
            "kind": "Deployment",
            "namespace": "default",
            "name": "legacy-app"
          },
          "ownerRef": null
        }
      ]
    }
  ],
  "summary": {
    "totalResources": 12,
    "byOwner": {
      "Flux": 10,
      "Native": 2
    }
  }
}
```

**Ordering:**
- `groups` sorted by canonical owner order
- `items` sorted by `(namespace, kind, name)`

**Lossless guarantee:**
- `items` contains ALL resources for this owner
- `displayMeta.maxItems` indicates what `--depth N` would show in ASCII
- ASCII renders: first N items + `(+M more)` where M = totalItems - maxItems

## 2. Trace Schema

**Command:** `cub-scout trace <resource> [--format json]`

**Purpose:** Why this resource exists (ownership chain to source)

```json
{
  "command": "trace",
  "target": {
    "kind": "Deployment",
    "namespace": "web",
    "name": "frontend"
  },
  "chain": [
    {
      "id": {
        "kind": "GitRepository",
        "namespace": "flux-system",
        "name": "flux-system"
      },
      "role": "source",
      "relationship": "sources",
      "evidence": [
        {
          "type": "field",
          "key": "spec.url",
          "value": "https://github.com/org/repo",
          "path": "spec.url"
        }
      ]
    },
    {
      "id": {
        "kind": "Kustomization",
        "namespace": "flux-system",
        "name": "web-apps"
      },
      "role": "deployer",
      "relationship": "applies",
      "evidence": [
        {
          "type": "field",
          "key": "spec.sourceRef.name",
          "value": "flux-system",
          "path": "spec.sourceRef"
        },
        {
          "type": "inventory",
          "key": "status.inventory",
          "value": "Deployment/web/frontend",
          "path": "status.inventory.entries"
        }
      ]
    },
    {
      "id": {
        "kind": "Deployment",
        "namespace": "web",
        "name": "frontend"
      },
      "role": "workload",
      "relationship": "managed-by",
      "evidence": [
        {
          "type": "label",
          "key": "kustomize.toolkit.fluxcd.io/name",
          "value": "web-apps",
          "path": "metadata.labels"
        },
        {
          "type": "label",
          "key": "kustomize.toolkit.fluxcd.io/namespace",
          "value": "flux-system",
          "path": "metadata.labels"
        }
      ]
    }
  ],
  "summary": {
    "ownerType": "Flux",
    "source": {
      "kind": "GitRepository",
      "namespace": "flux-system",
      "name": "flux-system",
      "url": "https://github.com/org/repo"
    },
    "deployer": {
      "kind": "Kustomization",
      "namespace": "flux-system",
      "name": "web-apps"
    }
  }
}
```

**Chain ordering:** source → deployer → workload (root to leaf)

**Roles:**
- `source` — Git/OCI/Helm repository
- `deployer` — Kustomization, HelmRelease, Application
- `workload` — Deployment, StatefulSet, etc.
- `intermediate` — ReplicaSet, Pod (if included)

**Relationships (canonical vocabulary):**
- `sources` — Source provides manifests to deployer
- `applies` — Deployer applies manifests to cluster
- `generates` — Generator creates downstream resources (e.g., ApplicationSet)
- `syncs` — Controller syncs resources (e.g., Argo Application)
- `manages` — Controller manages child resource
- `managed-by` — Workload back-reference to deployer
- `selects` — Service selects pods (label selector)

## 3. Map List Schema

**Command:** `cub-scout map list [--format json]`

**Purpose:** Flat list of resources with ownership attribution

```json
{
  "command": "map-list",
  "context": {
    "cluster": "prod-us-east",
    "namespace": null
  },
  "resources": [
    {
      "id": {
        "kind": "Deployment",
        "namespace": "api",
        "name": "backend"
      },
      "owner": {
        "type": "Flux",
        "ref": {
          "kind": "Kustomization",
          "namespace": "flux-system",
          "name": "api-apps"
        }
      },
      "status": "Ready"
    },
    {
      "id": {
        "kind": "Deployment",
        "namespace": "default",
        "name": "orphan"
      },
      "owner": {
        "type": "Native",
        "ref": null
      },
      "status": "Ready"
    }
  ],
  "summary": {
    "total": 2,
    "byOwner": [
      { "ownerType": "Flux", "count": 1 },
      { "ownerType": "ArgoCD", "count": 0 },
      { "ownerType": "Helm", "count": 0 },
      { "ownerType": "ConfigHub", "count": 0 },
      { "ownerType": "Native", "count": 1 }
    ],
    "byStatus": [
      { "status": "Ready", "count": 2 }
    ]
  }
}
```

**Ordering:** `resources` sorted by `(namespace, kind, name)`

**Summary arrays:**
- `byOwner`: Always includes all 5 canonical owner types in order: `[Flux, ArgoCD, Helm, ConfigHub, Native]`
- `byStatus`: Only includes non-zero counts, sorted alphabetically

**Status values:** `Ready`, `NotReady`, `Unknown`, `Progressing`, `Pending`

**Status normalization:** Empty or missing status is normalized to `Unknown`

**Command:** `cub-scout trace deploy/frontend -n web`

```

  ↑ sourced-from [spec.sourceRef.name=flux-system]
```

**JSON:** Same chain with structured evidence (see schema above)

## 4. Drift Schema (v0.14.4)

**Command:** `cub-scout drift [--format json]`

**Purpose:** What differs between desired (Git/OCI) and live (cluster) state

```json
{
  "command": "drift",
  "context": {
    "cluster": "prod-east",
    "namespace": "production",
    "desiredSource": {
      "type": "git",
      "ref": "abc123def456",
      "url": "https://github.com/acme/infra",
      "subpath": "clusters/prod"
    },
    "liveSource": {
      "type": "cluster",
      "ref": "prod-east"
    }
  },
  "findings": [
    {
      "id": "drift:Deployment:production/api:spec.replicas",
      "object_id": "Deployment:production/api",
      "object": {
        "kind": "Deployment",
        "namespace": "production",
        "name": "api"
      },
      "path": "spec.replicas",
      "desired": 3,
      "live": 5,
      "classification": "capacity",
      "severity": "warning"
    },
    {
      "id": "drift:Deployment:production/web:spec.template.spec.containers[0].image",
      "object_id": "Deployment:production/web",
      "object": {
        "kind": "Deployment",
        "namespace": "production",
        "name": "web"
      },
      "path": "spec.template.spec.containers[0].image",
      "desired": "nginx:1.19",
      "live": "nginx:1.20",
      "classification": "image",
      "severity": "critical"
    }
  ],
  "summary": {
    "totalFindings": 2,
    "bySeverity": [
      { "severity": "critical", "count": 1 },
      { "severity": "warning", "count": 1 }
    ],
    "byClassification": [
      { "classification": "capacity", "count": 1 },
      { "classification": "image", "count": 1 }
    ],
    "affectedObjects": 2
  }
}
```

**Ordering:** `findings` sorted by:
1. `severity` (descending: critical > warning > info)
2. `object_id` (ascending, lexicographic)
3. `path` (ascending, lexicographic)

This ordering is **semantic** (backed by `severity` JSON field), not narrative.

### Drift Path Formats (v0.14.4)

Paths use stable container name references (not indices) for determinism:

| Drift Type | Path Format | Example |
|------------|-------------|---------|
| Replicas | `spec.replicas` | `spec.replicas` |
| Image | `spec.template.spec.containers[<idx>].image` | `spec.template.spec.containers[0].image` |
| Env var | `spec.template.spec.containers[name=<name>].env[name=<var>]` | `spec.template.spec.containers[name=app].env[name=LOG_LEVEL]` |
| Resources | `spec.template.spec.containers[name=<name>].resources.<type>.<resource>` | `spec.template.spec.containers[name=app].resources.requests.cpu` |
| Pull policy | `spec.template.spec.containers[name=<name>].imagePullPolicy` | `spec.template.spec.containers[name=app].imagePullPolicy` |

**Design note:** Container name references (`[name=app]`) are preferred over indices (`[0]`) for:
- Stability across reordering
- Machine-joinable correlation with other findings
- Human readability

### Classification Values

| Classification | Description | Drift Types |
|----------------|-------------|-------------|
| `capacity` | Scaling and resource allocation | replicas, resource requests/limits |
| `image` | Container image changes | image tag, image repository |
| `config` | Configuration changes | env vars, configmap refs |
| `rollout` | Deployment strategy | imagePullPolicy, strategy |
| `health` | Health and readiness | probes, health checks |
| `label` | Label changes | label drift |
| `annotation` | Annotation changes | annotation drift |
| `other` | Unclassified | catch-all |

### Severity Values and Inference

| Severity | Meaning | Examples |
|----------|---------|----------|
| `critical` | Requires immediate attention | Different image repo, invalid resource config (limits < requests) |
| `warning` | Requires attention | Scale down, tag change, env change, policy change |
| `info` | Informational | Scale up (intentional HPA/manual) |

**Severity inference rules (v0.14.4):**
- Replicas: `live < desired` → warning, `live > desired` → info
- Image: different repo → critical, different tag → warning
- Env vars: any change → warning
- Resources: invalid config → critical, normal drift → warning
- Pull policy: any change → warning

**Summary arrays:**
- `bySeverity`: Canonical order (critical, warning, info), only non-zero counts
- `byClassification`: Canonical order (capacity, image, config, ...), only non-zero counts

**Source types:**
- `git` — Git repository (ref is commit SHA)
- `oci` — OCI artifact (ref is digest or tag)
- `file` — Local file path
- `cluster` — Live cluster (ref is context name)

**Stable IDs:**
- `id`: `drift:{object_id}:{path}` — unique per finding, stable for deduplication
- `object_id`: `{kind}:{namespace}/{name}` or `{kind}:{name}` for cluster-scoped

---

## Contract Guarantees

- JSON output is deterministic (same input = same output)
- JSON is lossless (display limits are metadata, not data loss)
- JSON is joinable (canonical `id` objects for cross-reference)
- JSON has no timestamps by default
- Evidence is structured and bounded (proof, not raw dump)
