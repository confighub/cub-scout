## Detailed Findings

### Issue 1: Demo `--list` Flag Mismatch

**Severity:** Low
**Component:** CLI help text

**Problem:**
```bash
$ ./cub-scout demo --help
# Shows: cub-scout demo --list

$ ./cub-scout demo --list
# Error: unknown flag: --list

$ ./cub-scout demo list
# Works correctly
```

**Expected:** Help text should match actual command syntax.

**Fix:** Update help text or add `--list` as flag alias.

---

### Issue 2: Demos Fail Without GitOps CRDs Pre-installed

**Severity:** High
**Component:** Demo system

**Problem:** Running `cub-scout demo quick` on a fresh cluster fails:

```
resource mapping not found for name: "podinfo" namespace: "atk-flux-basic"
from "flux-basic.yaml": no matches for kind "GitRepository" in version
"source.toolkit.fluxcd.io/v1"
ensure CRDs are installed first
```

The demo continues but shows only "Native" resources, defeating the purpose of demonstrating GitOps ownership detection.

**Impact:**
- New user's first experience is a broken demo
- User sees "By Owner: Native(22)" instead of Flux/ArgoCD ownership
- No indication of what went wrong or how to fix it

**Expected:**
- Demo should check prerequisites and provide guidance
- Or demo should be self-contained (mock mode, embedded CRDs)

---

### Issue 3: Trace Command Shows Healthy Resources as Errors

**Severity:** High
**Component:** `trace` command

**Problem:**
```bash
$ ./cub-scout trace deploy/podinfo -n atk-flux-basic

  ✗ GitRepository/podinfo           # Red X for healthy resource!
    │ Error: stored artifact for revision '6.5.0@sha1:2cbe0fc...'
    │                                # This is a SUCCESS message!
    └─▶ ✗ Kustomization/podinfo     # Red X again
        │ Error: Applied revision: 6.5.0@sha1:2cbe0fc...
        │                          # Also a SUCCESS message!

⚠ Chain broken at GitRepository/podinfo
```

Meanwhile, `gitops status` correctly shows everything healthy:
```bash
$ ./cub-scout gitops status
✓ All 1 deployers healthy
✓ GitRepository/podinfo
✓ Kustomization/podinfo
```

**Root Cause:** Trace command is not correctly parsing Flux status conditions. It's treating any status message as an error.

**Impact:** User sees red X and "Chain broken" for working deployments, causing confusion and distrust.

---

### Issue 4: risk issue Demo Broken

**Severity:** Medium
**Component:** `demo risk`

**Problem:**
```bash
$ ./cub-scout demo risk

Step 1: Deploying Grafana with the bug...
namespace/monitoring created
Error from server (NotFound): namespaces "grafana" not found

Step 2: Running risk issue scan...
✓ No issues found    # Should detect RISK-2025-0027!
```

The demo creates resources in `monitoring` namespace but references `grafana` namespace. The scan then reports "No issues found" even though the demo is supposed to demonstrate risk issue detection.

**Fix:** Correct the namespace references in `examples/impressive-demo/bad-configs/monitoring-bad.yaml`.

---

### Issue 5: Status Shows "Connected" With Expired Token

**Severity:** High
**Component:** `status` command

**Problem:**
```bash
$ ./cub-scout status
ConfigHub:  ● Connected    # Green, looks good!
Cluster:    default
Context:    kind-cub-scout-test

$ ./cub-scout import -n atk-flux-basic -y
Creating App Space... ✗
Error: create app space: exit status 1

$ cub space create test
Failed: token expired at 2026-01-24T15:15:37Z
```

The status command shows "Connected" with a green indicator even when the auth token is expired. Operations then fail with unhelpful error messages.

**Expected:** Status should validate token and show warning if expired.

---

### Issue 6: Import Error Messages Unhelpful

**Severity:** Medium
**Component:** `import` command

**Problem:**
```
Creating App Space: atk-flux-basic-team... ✗
Error: create space: create app space: exit status 1
```

The log file also lacks detail:
```
[08:08:39] FAILED: App Space creation: create app space: exit status 1
```

**Expected:** Propagate the actual error (e.g., "token expired") to the user.

---

### Issue 7: Orphan Detection Too Noisy

**Severity:** Low
**Component:** `map orphans`

**Problem:** Lists ALL native resources including:
- System ConfigMaps (`kube-root-ca.crt` in every namespace)
- Flux CRDs (GitRepository, Kustomization) - technically correct but confusing
- Flux controller Deployments
- Core Kubernetes services

This makes it hard to find actual "shadow IT" orphans among 39 listed resources.

**Suggestion:**
- Filter system namespaces by default (`--include-system` to show)
- Categorize orphans (system, gitops-config, user-created)

---

### Issue 8: Platform-example setup.sh Requires Interactive Input

**Severity:** Low
**Component:** Examples

**Problem:** Script blocks on:
```bash
read -p "Continue anyway? (y/n) "
```

Cannot run in automated/CI environments.

**Fix:** Add `-y` or `--force` flag, or use `FORCE=1` env var.
