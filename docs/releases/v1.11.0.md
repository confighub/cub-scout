# v1.11.0 Release Notes

> **Status:** Released 2026-04-11.
> Previous milestone: `v1.10.0` strengthened troubleshooting with recent Kubernetes events in `explain` and `trace`.

**Theme:** *Make cub-scout easier to choose, easier to route, and easier for AI to use correctly.*

This release tightens the product surface after the v1.10 troubleshooting work. The command tree is smaller and more coherent, the MCP gateway exposes a more complete troubleshooting path, and the docs/AI onboarding story now points humans and agents at the right surfaces faster.

---

## What's New

### Smaller, Clearer Command Surface

`cub-scout` now has a more coherent top-level CLI.

Highlights:
- reduced visible top-level command sprawl
- `compare` is now the canonical name, with `combined` kept as a hidden compatibility alias
- setup and import flows are grouped under clearer command families
- old top-level entrypoints continue to work as hidden deprecated aliases for one release

Canonical paths now include:

```bash
cub-scout setup connect
cub-scout setup completion
cub-scout import apply
cub-scout import argocd
cub-scout import cluster-aggregator
cub-scout import parse-repo
cub-scout compare drift
cub-scout quickstart demo
```

This makes the CLI easier to learn, easier to document, and easier for AI assistants to route correctly on a cold start.

### Stronger MCP Gateway for Troubleshooting

The MCP gateway now exposes a more complete connected troubleshooting path.

New and improved:
- sharper MCP tool descriptions for cold-start tool selection
- clearer standalone vs connected tool identity
- `compare_three_way` added to the MCP gateway in connected mode

That means an AI client can now reach a fuller proof chain through MCP:
- `doctor`
- `explain`
- `trace`
- `compare_three_way`

without dropping back to shell-first guessing for governed-vs-live comparison.

### AI Onboarding and Skill Cleanup

The AI-facing entrypoints are now cleaner and more intentional.

Included in this release:
- duplicate cub-scout skill files reconciled
- one canonical repo-local skill path retained
- AI gateway value-test guide added
- cold-test prompts added for repeatable MCP-vs-shell evaluation

This makes it easier to evaluate whether the AI gateway is adding real value, not just tool access.

---

## Documentation Overhaul

This release substantially tightens the docs hierarchy.

The canonical structure is now:

- `README.md` for overview and fast path
- `CLI-GUIDE.md` for workflow-first usage
- `docs/reference/cli-reference.md` for A-Z command catalog
- `docs/reference/commands.md` for detailed usage and examples
- `docs/reference/cli-contract.md` for stable contract expectations

### README Trim and Restructure

The README was rewritten from a long mixed-purpose document into a shorter front door.

Changes:
- reduced from 845 lines to 293 lines
- kept only the highest-signal onboarding content
- moved deeper command detail into canonical reference docs
- made AI entrypoints and interface choices easier to find

### CLI Docs Consolidation

Overlapping CLI references were consolidated and aligned with the new command tree.

Also included:
- command inventory verification script:
  - `go run ./scripts/check-cli-docs`
- link and structure checks for the canonical CLI doc set

### Canonical Import Paths

Docs and examples now consistently use canonical import subcommands:

```bash
cub-scout import argocd
cub-scout import cluster-aggregator
cub-scout import parse-repo
```

Deprecated top-level aliases still work for compatibility, but the docs now point to the canonical paths.
