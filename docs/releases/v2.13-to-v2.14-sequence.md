# Release execution sequence: v2.13, then v2.14

Written 2026-10-05. Execution owner: [#645](https://github.com/confighub/cub-scout/issues/645).
This is the task order for the existing [adopted plan](../roadmap-3.0-execution.md),
using the latest [handover](../../HANDOVER.md). It adds no gate waiver or new
release allocation. **All required tests are in scope, including live tests.**
Neither v2.13 nor v2.14 is published; the published baseline is v2.12.4.

Use the sequence below as the default order. Complete a task's dependency and
exit proof before advancing its dependent task. A failed test returns work to
the repair responsible for it; retain the failure and rerun affected checks.
Run local live lanes serially, in owned disposable environments. Scout stays
read-only; fixture setup belongs to the test harness. Preserve shared clusters,
server data and global contexts. Keep frozen benchmark questions, raw evidence,
ordinary-tool grants, graders and per-case budgets unchanged.

## Checks attached to every implementation packet

Define exact positive/negative fixtures, a worked example, graceful degradation
and the relevant standalone/connected/per-cluster aggregation proof before code.
Add an authored eval for changed agent-facing behavior without rewriting the
frozen held-out benchmark. Run focused tests first; then the required full suite
on stable source without overlapping heavy Go builds/race jobs:

```sh
go build ./cmd/cub-scout
go test ./...
go vet ./...
./scripts/check-readonly.sh
./scripts/check-cli-guide-parity.sh
./scripts/check-no-personal-names.sh
```

Run affected race/integration/golden suites, packet Python guards and the named
live proof as well. Record exact argv, exit status, source/artifact versions,
timestamps, raw hashes, scope and cleanup. Review the final semantic diff and
inspect SHA-bound CI evidence. Retain failures. Never count skipped required
assertions, fabricated server decisions or old-source successes as a passed gate.

Keep the adopted P5/P6 work allocated to its milestones: fact-store publication,
default ongoing reuse/history and the 3.0 compatibility removals. Existing
watch/bot conformance remains required above. The SDK migration stays deferred;
Scout gains no renderer responsibilities. Product docs contain no competing
product names. New scope must be tracked before implementation.
