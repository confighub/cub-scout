# v2.12.0 - Working With cub v0.5.2, and ConfigHub Evidence That Says Only What Is Known

Previous release: v2.11.0. This document defines the release scope, not proof
that a pending check passed.

## User Value

**"Does cub-scout still work with the current cub?"** — `cub` v0.5.2 removed the
default space: a `cub ... list` with no `--space` now reads the whole
organization, and `cub context set` is gone. v2.11.0 read the leftover
`defaultSpace` from old cub configs and scoped reads to a space cub no longer
uses, and some reads sent no space at all. This release names the space on
every `cub` call, refuses rather than widen, and says which space it read.

**"Can I trust what ConfigHub evidence tells me?"** — release, unit-event,
fleet, impact and compare output stop claiming more than ConfigHub reports.

## What's in it

### Explicit ConfigHub space ([#560](https://github.com/confighub/cub-scout/pull/560), [#552](https://github.com/confighub/cub-scout/issues/552))

- A space comes from `--space` (or the resource itself), else `CUB_SPACE`, and
  from nowhere else. A `defaultSpace` left in an old cub config is ignored, as
  cub ignores it.
- `history`, `audit list`, `tree config`, `impact` and `fleet outliers` refuse
  without a space; `history`, `audit list` and `impact` gain `--space`. Output
  reports the space read (`scope`).
- `map fleet` reads every space by default, explicitly, and says so.
- MCP `confighub_units` and `confighub_changesets` require `space`;
  `confighub_unit_get` takes `space` or a `<space>/<slug>` or ID reference.
- `impact` no longer makes a unit its own dependent through a link to a
  same-named unit in another space. `status` reads cub's worker list (its parser
  never matched cub's output) and says exactly what it looked for. `compare`
  uses the space ID current releases stamp.
- `fleet outliers` reports that nothing was compared when no unit is on two
  clusters, which is always the case within one space, instead of reporting
  every cluster as missing units. Cross-space comparison needs unit lineage
  ([#562](https://github.com/confighub/cub-scout/issues/562)).
- See [`examples/confighub-space-scope/`](../../examples/confighub-space-scope/).

### ConfigHub evidence that says only what is known ([#550](https://github.com/confighub/cub-scout/pull/550), [#557](https://github.com/confighub/cub-scout/pull/557))

- Release rows arrive at all: the read no longer selects fields ConfigHub
  rejects.
- A Release that is no longer served is `release-not-published`, not
  "published"; `doctor` counts rows in the time window, not rows kept.
- Unit events carry their unit and space, so they can be joined; a failed Apply
  (`Result: None`, `Status: Failed`) is raised by `doctor`.
- Release joins are target-level, and output says so.

### Connected gate follows the cub login ([#556](https://github.com/confighub/cub-scout/pull/556), [#551](https://github.com/confighub/cub-scout/issues/551))

- Connected-only commands check `cub auth status`, which notices an expired
  session, and pass cub's own reason through.

### cub CLI hygiene ([#565](https://github.com/confighub/cub-scout/pull/565), [#566](https://github.com/confighub/cub-scout/pull/566), [#567](https://github.com/confighub/cub-scout/pull/567))

- Every `cub` call passes `-o json` instead of the deprecated `--json`.
- The import wizard no longer uses cub's deprecation notice as a target slug,
  and reads data it writes back from stdout alone.
- Connected `compare` stops calling the removed `cub unit livedata`, keeps DRY,
  and reports `dry-live`.
- The TUI shell no longer sets `CUB_CONTEXT` to the kube context, which broke
  every `cub` command in it.

## Upgrade

```sh
# Existing plugin installation:
cub plugin upgrade scout@v2.12.0
cub scout version
# Fresh plugin installation:
cub plugin install confighub/cub-scout@v2.12.0
```

Pass `--space` (or export `CUB_SPACE`) to connected commands that read one
space. MCP clients calling `confighub_units`, `confighub_changesets` or
`confighub_unit_get` must pass `space`, or a qualified unit reference.

## Proof and limits

- Tested against `cub` v0.5.2 and a ConfigHub v0.5.1 server, recording every
  `cub` call: no call without a space on a space-scoped entity, no `--json`, no
  reads of the context default.
- **Not proven live:** the import wizard's test apply and `import argocd` write to
  ConfigHub, so they are proven against a fake `cub`; the connected `compare`
  path had no linked workload to run against.
- **Still tracked:** OCI-delivered objects are not recognised from current
  `/space/<slug>` OCI URLs ([#561](https://github.com/confighub/cub-scout/issues/561));
  one `cub` runner that enforces `--space` at run time ([#563](https://github.com/confighub/cub-scout/issues/563));
  converging the remaining connected gates ([#558](https://github.com/confighub/cub-scout/issues/558)).
