# v2.13.0 — Scoped, explainable investigation evidence

**Draft — unreleased.** Published baseline remains v2.12.4. This describes the
current candidate scope; it is not a tag, release announcement or acceptance
record. [Readiness](v2.13-readiness.md) and the
[execution tracker](https://github.com/confighub/cub-scout/issues/645) govern
remaining gates.

## Candidate changes

- Explicit context and namespace binding across investigation workflows, with
  shared CLI/MCP/TUI facts and honest denied/partial observations. Per-call
  selection does not switch the shared kubectl context. Context labels alone
  do not establish stable cluster identity.
- Exact-space ChangeOrder reads preserve reported Stage/State and prerequisite
  declarations. Reported completion does not establish evaluated approval,
  gate acceptance or application health.
- Exact combined-origin revision claims appear on trace/explain, the connected
  MCP reader and receipt supporting evidence. Expiry and observed revocations
  remain visible, with partial and effective-coverage omissions. Receipts verify
  served revision bytes before retaining DataHash beside their canonical subject
  digest; these facts do not change the runtime verdict or evaluate approval.
- Sveltos ClusterSummary delivery features and ClusterHealthCheck continuous
  health conditions remain separate, with source identities, reported target
  references/timestamps, deterministic bounds and explicit omissions. Current
  workload health and check execution freshness remain unknown.
- Recorded map/explain input supports exact apps/v1 DeploymentList envelopes,
  deriving only omitted item type fields and exposing that derivation alongside
  the unchanged original-source hash. Recorded input remains historical;
  capture time and completeness are not inferred.
- Delivery identity and bounded Helm decoding work improve conservative
  observations. Genuine server/controller/lifecycle acceptance still needs the
  named remaining gates.
- Public Go imports use `/v2`. Local external-consumer verification is complete;
  public proxy installation must be verified after the release tag exists.
