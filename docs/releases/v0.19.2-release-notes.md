# cub-scout v0.19.2 — Documentation Closure & Clarity

**Release date:** 2026-02-05
**Theme:** *Everything that exists is understandable*

v0.19.2 is a **documentation-only release** focused on closing gaps identified during v0.19 onboarding and UX review.
No behavior, semantics, or outputs have changed.

This release makes the **current system fully legible** — especially for new users and reviewers.

---

## What's Improved

### Complete CLI Coverage

All public commands are now documented in **CLI-GUIDE**:

* `graph`, `bundle`, `catalog`, `patterns`, replay and diff commands
* Each command includes:

  * What it does
  * When to use it
  * Example usage
  * Common pitfalls
  * Related commands

There are no longer any "mystery commands".

---

### Unified Testing Documentation

Testing documentation has been consolidated into a **single authoritative entry point**:

* Clear test taxonomy and intent
* Explicit contract and determinism guarantees
* Canonical scripts and CI flows

> If a behavior matters, it has a golden file, snapshot, or hash.

---

### Improved Discoverability

* FAQ is now linked from the main README
* Broken diagram references removed or repaired
* Docs navigation is consistent from README → demos → CLI → testing

---

### New User Guidance (Optional, Not Prescriptive)

Added a short **optional sanity checklist** near demos and connected-mode docs to help new users avoid common setup pitfalls — without introducing rules or barriers.

---

### Orphan Detection Filtering (#114)

The `map orphans` command now filters system namespaces by default to reduce noise:

* `kube-system`, `kube-public`, `kube-node-lease`
* `flux-system`, `argocd`, `cert-manager`, `ingress-nginx`, `local-path-storage`

Use `--include-system` to show all namespaces.

---

### Non-Interactive Scripts (#115)

Example scripts now support automation/CI usage:

* `-y` / `--yes` flag to skip confirmation prompts
* `CUB_SCOUT_ASSUME_YES=1` environment variable
* Auto-yes when stdin is not a TTY
* `--batch` mode for demo scripts (skips pauses)

---

## What Did *Not* Change

* No semantic or contract updates
* No behavior or output differences beyond orphan filtering defaults
* All existing tests pass

v0.19.2 exists purely to **reduce cognitive friction** and improve confidence.

---

## Why This Release Exists

v0.19 delivered major UX and TUI improvements.
v0.19.1 hardened correctness and trust.

**v0.19.2 finishes the job** by ensuring that:

* Everything shipped is explained
* Everything explained is discoverable
* Nothing feels missing or implied
