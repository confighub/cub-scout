# v2.12.4 — More accurate answers and smaller agent reads

**Release preparation: 2026-09-30. Not yet published.** Previous release: v2.12.3.

This patch corrects ownership attribution and workload health, preserves useful
MCP answers, and lets agents request a compact inventory instead of reading every
resource. These changes enable lower-cost investigations; they do not establish
a general savings claim. The controlled benchmark is tracked in #603 and #645.

## Changes

- #625: kubectl set, rollout, label, annotate, expose and autoscale managers are
  recognised as hand edits, rather than attributing their changes to GitOps.
- #629: an Argo tracking-id takes precedence over a copied instance label.
- #630: MCP retains structured command output when the command exits non-zero,
  including the expected unmanaged-resource result from trace.
- #631: attribution questions route to scout-attribute; the remaining routing
  work stays in #626.
- #634: scaled-to-zero Deployments, DaemonSets and image-pull failures receive
  appropriate health classifications instead of a generic Pending result.
- #637: MCP map supports kind, owner, query, summary, names_only and count;
  CLI map list adds --summary. Existing full JSON output remains available.
- #640: scan, doctor, landing-page and recovery hints preserve `cub scout`
  invocation in plugin mode and `cub-scout` in standalone mode. An additional
  scan --list regression fails before the fix and passes afterward.
- #643: live-only eval cases, stricter exact-answer regexes and an explicit
  incomplete-result report support honest measurement. This is harness work,
  not evidence that the savings gate has passed.
