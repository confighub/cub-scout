# v2.11.0 - Identity-Linked Release Checks and Cheaper Observation

> **Status: prepared, not yet published.** The changes below are merged to `main`
> but no `v2.11.0` tag or GitHub release exists yet. Install commands in the
> README stay pinned to v2.10.1 until this release is tagged. This document
> defines the release scope, not proof that a pending check passed.

Previous release: v2.10.1.

## User Value

Two themes, both extending trust without changing the read-only boundary.

**"Is my intended release actually running?"** — the release-verification story
gains identity-linked evidence, kept in explicit, separately-falsifiable tiers.

**"Can I leave this watching without hammering the cluster?"** — long-running
`watch`/`bot` observation gets measurably cheaper, and now reports deletions.

## What's in it

### Identity-linked release verification

- **Controller-revision evidence** ([#535](https://github.com/confighub/cub-scout/pull/535)):
  `explain --expected-revision` compares an explicit Git commit or SHA-256
  artifact digest with a single-source Application or v1 Kustomization report —
  `match` / `mismatch` / `unknown`, with the original reported revision and
  separate controller status. No ConfigHub auth; same two-request cold read.
- **Exact OCI configuration release check** ([#536](https://github.com/confighub/cub-scout/pull/536)):
  `release check` verifies a digest-pinned OCI configuration bundle against the
  selected controller's repository/target/inventory binding, then compares
  authored live fields and workload-controller convergence. Bundle, controller,
  configuration and convergence are separate, explicitly-bounded results across
  CLI/plugin, MCP and a refreshable TUI.
- **Running-image identity** ([#538](https://github.com/confighub/cub-scout/pull/538)):
  opt-in `release check --check-running-image` compares the digest running in
  live pods (`.status.containerStatuses[].imageID`) with the intended workload
  image. A mutable tag stays `UNKNOWN` (pin to a digest to confirm); a differing
  digest is `MISMATCH` with a multi-architecture caveat, never a false alarm; the
  headline never claims running when it is unconfirmed. The configuration-bundle
  digest and the container-image digest are separate identities, never compared.

### Cheaper long-running observation

- **Polling baseline** ([#533](https://github.com/confighub/cub-scout/pull/533)):
  a measured request/response-byte baseline for the polling collector, so
  efficiency changes are proven, not asserted.
- **Within-cycle read coalescing** ([#540](https://github.com/confighub/cub-scout/pull/540)):
  a per-cycle memoizing client shares one read of each type between the inventory
  sweep and the state scan, cutting each cycle from 48 to 43 requests and removing
  duplicated list bytes, with no change to observed data.
- **Watch-backed idle observation** ([#541](https://github.com/confighub/cub-scout/pull/541),
  [#542](https://github.com/confighub/cub-scout/pull/542)): opt-in
  `watch`/`bot --watch-backed` serves inventory **and** the state scan from a
  Kubernetes watch informer cache, so an idle cycle makes essentially no list API
  calls. Only served, synced types are cached; any setup failure falls back to
  per-cycle polling, so coverage never silently degrades.
- **Deletion events**: a new `resource.deleted` watch event surfaces a resource
  that was present last cycle and is now gone — previously silent, in both polling
  and watch-backed modes. Watch-backed cycles stamp `observation.mode:
  watch-informer`.

### Installation

- **Local bot images from verified release archives** ([#537](https://github.com/confighub/cub-scout/pull/537)):
  `examples/bot/build-from-release.sh <version> <arch>` verifies the published
  Linux archive checksum before building a local amd64/arm64 non-root image, for
  environments where the public registry pull is unavailable. No ConfigHub auth,
  image push, registry-permission change, or cluster deployment; it does not
  repair public registry access.

### Repository

- **`AGENTS.md`** ([#543](https://github.com/confighub/cub-scout/pull/543)): the
  codex-convention agent guide is now tracked and reconciled with `CLAUDE.md`.

## Upgrade (once published)

```sh
# Existing plugin installation:
cub plugin upgrade scout@v2.11.0
cub scout version
# Fresh plugin installation:
cub plugin install confighub/cub-scout@v2.11.0
```

Standalone users upgrade through Homebrew or the checksum-verified
[archives](../getting-started/install.md#download-binary). Restart long-running
MCP/watch/bot processes to load the new binary.

## Proof and limits

Every capability ships with deterministic tests, a worked example or explicit
limitation, and README User-questions coverage; `go test ./...` (including race
detection on the observation paths) and the CLI-docs parity check pass.

- **Opt-in surfaces stay opt-in.** `--check-running-image` and `--watch-backed`
  are off by default; default request budgets and behavior are unchanged.
- **Bounded, honest degradation.** Mutable tags, unreadable pods, unsynced or
  RBAC-denied types resolve to a specific `UNKNOWN`/fallback, never a false
  positive or a false "nothing changed".
- **Separate identities.** Configuration-bundle digest, intended image reference,
  and running image digest are never conflated.
- **Read-only boundary intact.** No cluster mutation, no deployment, no status
  writeback; delivery and application-success policy stay with their owners.
- **Still tracked:** running-image registry-side index/digest resolution and full
  watch-backed freshness signalling ([#502](https://github.com/confighub/cub-scout/issues/502)/[#505](https://github.com/confighub/cub-scout/issues/505)/[#539](https://github.com/confighub/cub-scout/issues/539));
  container distribution and registry-pull gaps ([#520](https://github.com/confighub/cub-scout/issues/520)).
