# v3.1.0 — Pre-write safety sensor, offline signed receipts, Argo Rollouts, and blast-radius

**Published on 2026-11-26.** The release before it is [v3.0.0](v3.0.0.md).

`v3.1.0` turns `cub-scout` from a post-deploy witness into a complete,
strictly read-only **agent write loop** — pre-write safety sensing
(`before-write`), offline Ed25519 signed receipts (`receipt sign` / `verify`),
full offline `--recording` parity including `trace` and sanitized Pods/PDBs,
standard `answer` envelopes on `watch` and `bot` streams, multi-arch GHCR bot
deployment, Argo Rollouts parity, and ephemeral offline `graph blast-radius` —
without adding a single cluster write or a single unapproved `answer.state`
word.

---

## Highlights

### 1. Pre-write safety sensor: `cub scout before-write` & MCP `before_write` ([#1027](https://github.com/confighub/cub-scout/pull/1027))
- New top-level command `cub scout before-write <kind/name> -n <ns> [--field-path <path>] [--recording <file>] [--format ascii|json|md]`
  and standalone read-only MCP tool `before_write`.
- Composes ownership detection, `fieldAttribution` (live value, `managedFields`
  writers, G5 `agent/<tool>[/<run>]` contention, `revertPrediction`), Flux
  `spec.suspend` / Argo CD `autoSync`/`selfHeal`/`syncWindows`, and matching
  `policy/v1` `PodDisruptionBudget`s into one bounded `< 1 KB` read-only answer.
- Reuses `explain`'s approved `answer.state` vocabulary (`explained`,
  `not-observable`) with zero new state words.
- Supports offline `--recording <file>` evaluation (rejecting `--kube-context`
  and emitting an explicit `kind: stale` unknown).

### 2. Offline Ed25519 receipt signing & verification (`signed-receipt/v1`) ([#1026](https://github.com/confighub/cub-scout/pull/1026), Refs `#889`)
- New offline subcommands using Go stdlib cryptography only (zero network or
  Kubernetes calls):
  - `cub scout receipt keygen --out-private <priv.pem> --out-public <pub.pem>`
  - `cub scout receipt sign --input <file|-> --key <priv.pem> [-o <out.json>]`
  - `cub scout receipt verify --input <signed.json|-> --pubkey <pub.pem> [--format ascii|json]`
- Signs both `receipt/v1` in-toto Statements and `cub scout landed --format json`
  payloads with deterministic canonical JSON hashing (`signed-receipt/v1`
  envelope: `ed25519`, `keyId`, `payloadDigest`, base64 `signature`, RFC 3339
  UTC `signedAt`, raw `payload`).
- Exits non-zero on tampered payloads or mismatched public keys.

### 3. Offline `trace --recording` & sanitized Pod/PDB snapshots ([#1028](https://github.com/confighub/cub-scout/pull/1028))
- `cub scout trace <kind/name> -n <ns> --recording <file>` reconstructs
  deterministic delivery chains offline for Flux (`Kustomization`,
  `HelmRelease`, `GitRepository`, `OCIRepository`), Argo CD (`Application`),
  Helm (release Secrets), kro, and Crossplane, reusing `buildTraceAnswer` with
  an explicit `kind: stale` unknown naming the snapshot `observedAt`.
- `cub scout snapshot --format yaml|json` now captures `policy/v1`
  `PodDisruptionBudget`s and strictly sanitized `core/v1` `Pod`s (preserving
  safe metadata, container names/images, and `status.containerStatuses[].imageID`
  for offline `landed --verify-pod-images`, while stripping `env`, `envFrom`,
  `args`, `command`, `volumeMounts`, `volumes`, and
  `last-applied-configuration`).

### 4. Standard `answer` envelope & byte ceilings on `watch` and `bot` ([#1025](https://github.com/confighub/cub-scout/pull/1025), Refs `#596`)
- Additive `answer` envelope on `watch` and `bot` events (both JSONL file and
  webhook sinks), reusing `doctor`'s approved `answer.state` vocabulary
  (`issues-flagged`, `nothing-flagged`, `incomplete`, `not-observable`).
- All untrusted cluster text (finding messages, ownership transitions, omission
  reasons) is quoted in `basis[].quoted` / `unknowns[].quoted`, with safe
  guarding on `Ref`, `Summary`, and `Next`.
- Compact JSON byte ceiling (`<= 700` bytes) enforced in
  `answer_size_ceilings_test.go` and `bot_answer_test.go`.

### 5. Multi-arch GHCR `cub-scout bot` image & hardened read-only deploy kit ([#1029](https://github.com/confighub/cub-scout/pull/1029), Refs `#520`)
- Multi-arch (`linux/amd64`, `linux/arm64`) non-root `ghcr.io/confighub/cub-scout`
  container release wiring in `.goreleaser.yaml` and `.github/workflows/release.yaml`.
- Hardened read-only (`get`/`list`/`watch` only, non-root, read-only root
  filesystem, dropped capabilities) deploy kit in `examples/bot/`
  (`deployment.yaml`, `rbac-readonly.yaml`, `README.md`) backed by
  `test/unit/bot_release_image_test.go`.

### 6. Argo Rollouts parity across `landed`, `before-write`, `trace`, and `snapshot` ([#1031](https://github.com/confighub/cub-scout/pull/1031), Refs `#596`, `#645`)
- First-class `argoproj.io/v1alpha1` `Rollout` (`ro`/`rollout`/`rollouts`)
  support across `landed` (including `--verify-pod-images` via `spec.selector`),
  `before-write`, `trace`, and `snapshot`.
- Preserves the zero false-landed invariant (`Healthy` + current generation →
  `landed`, `Paused` / `Progressing` / generation lag → `converging`,
  `Degraded` → `not-landed`) with zero new `answer.state` words.

### 7. Ephemeral offline `graph blast-radius` & bytes benchmark ([#1032](https://github.com/confighub/cub-scout/pull/1032), Refs `#596`, `#645`)
- Strictly read-only offline `cub-scout graph blast-radius <kind/name> -n <ns> --recording <file> [--format ascii|json]`
  building an ephemeral in-memory dependency graph (`ancestors[]`,
  `descendants[]`, `affectedWorkloads[]`) across `ownerReferences`, Flux
  `sourceRef`/`chartRef`/`dependsOn`, Argo CD `instance`/`tracking-id`,
  ConfigMap/Secret refs, and PDB selectors; bounded at 50 nodes (`truncated`),
  cycle-safe, with explicit `observedAt` staleness.
- Zero-credit 4-case multi-controller benchmark
  (`evals/scripts/measure_blast_radius.py`): **54,534 raw bytes → 9,279
  blast-radius JSON bytes (82.98% overall reduction; 89.65% on 4-hop Flux)**,
  with 4-hop compact JSON enforced at **1,084 bytes <= 1,200**.

### 8. Front-door documentation & agent write-loop guide ([#1030](https://github.com/confighub/cub-scout/pull/1030), Refs `#645`)
- Added [docs/howto/agent-write-loop.md](../howto/agent-write-loop.md)
  covering the end-to-end read-only loop (`before-write` → write →
  `landed --verify-pod-images` → offline `--recording` → Ed25519
  `receipt sign`/`verify` → `--view summary` / `--if-unchanged` token budgets).
- Refreshed `README.md` and `docs/getting-started/start-here.md` around the
  `v3.0` / `v3.1` agent write-loop workflow.

established in [v3.0.0](v3.0.0.md).
