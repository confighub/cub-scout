# v1.1.0 Release Notes

> **Status:** Released 2026-02-25.
> Predecessor: `v1.0.0` (2026-02-20).

**Theme:** *Connected foundation and scan integration — making connected mode clearly better than standalone, and preparing the scan boundary for confighub-scan.*

This release completes Phase A (trust hardening), Phase B (connected foundation), and the scan provider boundary of the 1.x roadmap.

---

## What's New

### Connected Hierarchy Navigation

Connected mode now provides smarter defaults:
- **Cluster-aware filtering** — auto-scopes views to the connected cluster context
- **Mode-aware query presets** — different default queries for Standalone vs Connected
- **Auto-navigation** — TUI navigates to App Hierarchy when connected

### Mode State Visibility

The TUI now clearly displays operating mode:
- **QuickMode** for instant mode detection without API calls
- **Offline / Standalone / Connected** distinction visible in status bar
- No ambiguity about what data sources are active

### Trace Context Diagnostics

When trace fails due to stale context, cub-scout now provides structured remediation:

```
Flux context error detected

  Flux CRDs or controllers may not be installed in this cluster.

  Remediation:
    1. Verify cluster access:    kubectl cluster-info
    2. Check Flux installation:  flux check
    3. Install Flux if missing:  flux install
    4. Switch context if needed: kubectl config use-context <name>
    5. Retry:                    cub-scout trace <resource>
```

Supported tools: **Flux, Helm, ArgoCD, ConfigHub**. ConfigHub enrichment failures never block standalone trace.

See: `docs/howto/trace-context-troubleshooting.md`

### Scan Provider Boundary

Scan execution is now abstracted behind a `Provider` interface (`internal/scan/`):

- **`LegacyProvider`** wraps the existing `pkg/agent` scanners (default, ships today)
- **`ConfighubScanProvider`** stub delegates to `confighub-scan` binary when available, falls back to legacy
- **Config resolution chain** — explicit flag > `CUB_SCOUT_KYVERNO_DB` env > filesystem probe
- **`--normalized-json`** flag outputs `scan.normalized.v1` schema — unified findings shape across all 7 scanner tracks (kyverno, state, timing-bomb, unresolved, dangling, static, lifecycle)
- **Contract test suite** validates both providers against shared assertions

`cmd/cub-scout/scan.go` is now a thin rendering adapter; providers own orchestration.

### App-Centric Transition Mapping

Import CLI help, README, and `commands.md` now reference the glossary's App/Deployment ↔ Space/Unit mapping table, reducing terminology confusion as 1.x scope evolves.
