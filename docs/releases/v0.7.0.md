# v0.7.0 — Pattern Engine MVP

**Release date:** TBD

v0.7 introduces the **Pattern Engine**, a deterministic framework for analyzing
resource graphs and detecting structural patterns.

## New Commands

### `cub-scout patterns list`

Lists all registered patterns with their IDs and names.

### `cub-scout patterns detect`

Runs all registered patterns against the cluster's resource graph.

```bash
cub-scout patterns detect              # Text output
cub-scout patterns detect --json       # JSON output
cub-scout patterns detect -n prod      # Specific namespace
cub-scout patterns detect --empty      # Empty graph (testing)
```

**Exit codes:**
- `0` — All patterns passed
- `4` — One or more patterns failed

### `cub-scout patterns explain <pattern-id>`

Explains a specific pattern and shows its detection results.

```bash
cub-scout patterns explain k8s.ownership_chain_complete
cub-scout patterns explain gitops.controller_presence -n prod
```

**Exit codes:**
- `0` — Success (pass or skip)
- `2` — Usage error
- `3` — Unknown pattern ID
- `4` — Pattern failed

## Registered Patterns

### `k8s.ownership_chain_complete`

Checks that Deployment → ReplicaSet → Pod ownership chains are complete.
Detects orphaned ReplicaSets and Deployments without ReplicaSets.

### `gitops.controller_presence`

Detects the presence of GitOps controller CRDs:
- Argo CD: Applications, ApplicationSets
- Flux: Kustomizations, HelmReleases, GitRepositories

## Schema

Output includes `schema_version: "patterns.v1"` for compatibility checks.

See [Patterns Contract Reference](../reference/patterns-contract.md) for full documentation.

## Non-goals (v0.7)

The following are explicitly **out of scope** for this release:

- **Pattern inference from Git** — Patterns operate purely on graph data
- **Confidence scoring** — Findings are binary (detected or not)
- **Remediation hints** — Findings describe problems, not fixes
- **Pattern composition** — No pattern dependencies or prerequisites
- **ConfigHub integration** — No connected-mode enrichment

These may be addressed in future releases.

## Contract Discipline

v0.7 follows the same contract discipline as v0.5 and v0.6:

- Output formats are stable and deterministic
- Exit codes are consistent and documented
- Schema version is explicitly declared
- Golden tests lock behavior

This is a **new contract surface** — it does not modify any v0.5 or v0.6 contracts.

## Upgrade Notes

No breaking changes. v0.7 is purely additive.
