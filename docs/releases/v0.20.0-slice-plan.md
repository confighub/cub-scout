# v0.20.0 Slice Plan — Flux Operator Interop (Read-Only)

**Status:** Proposed  
**Date:** 2026-02-11  
**Audience:** Maintainers and contributors planning the next standalone CLI increment

## Why This Slice Exists

Flux Operator v0.41 shipped a strong operator workflow set in Web UI:

- CronJob and Job visibility
- On-demand Job runs from CronJobs
- Rollout restart and pod deletion actions
- Source artifact access
- Better action/audit tracing
- PR preview workflow support (Gitea/Forgejo)

This slice defines what `cub-scout` should add in a **read-only, deterministic CLI form**.

## Scope Theme

**"Operate confidently from evidence, without adding mutation."**

## Non-Goals

- No controllers, no background agents
- No direct action execution (no restart/delete/run-now mutation by `cub-scout`)
- No rewrite of canonical workload definition for existing commands
- No dependency on Flux Operator UI internals

## Contract Guardrails

- Existing canonical workload scope remains unchanged in `map workloads`:
  - `Deployment`
  - `StatefulSet`
- New concerns are exposed through new commands/flags, not silent behavior drift.
- JSON stays canonical data; ASCII/Markdown are renderings of JSON fields.

## Feature Set (Must Ship)

### 1) CronJob and Job Visibility

### Command Surface

```bash
cub-scout map cronjobs [--namespace <ns>] [--owner Flux|Native] [--format ascii|json|md]
cub-scout map jobs [--namespace <ns>] [--owner Flux|Native] [--format ascii|json|md]
```

### Required Data

- `schedule`
- `suspend`
- `lastScheduleTime`
- `activeJobs`
- `lastRunStatus` (`success|failed|running|unknown`)
- `owner` (Flux/Native/etc.)
- lineage reference where available (Flux source/kustomization/helmrelease)

### Acceptance Criteria

- `map cronjobs` returns deterministic ordering (namespace, name).
- `map jobs` links Jobs to CronJob owner when ownerReference exists.
- JSON output has stable top-level keys and deterministic list order.

### 2) Read-Only Action Preview (Runbook Generator)

### Command Surface

```bash
cub-scout map actions <kind/name> -n <namespace> [--format ascii|json|md]
```

### Behavior

Show preview-only operator actions and impact notes:

- `rollout restart` for Deployment/StatefulSet/DaemonSet
- `kubectl delete pod` guidance for Pod
- `kubectl create job --from=cronjob/<name>` guidance for CronJob

### Required Output Fields

- `actionType`
- `commandPreview`
- `riskLevel`
- `requiresConfirmation`
- `whySuggested`
- `expectedImpact`

### Acceptance Criteria

- Command never mutates cluster.
- Every suggested action includes a rationale and risk level.
- JSON schema is stable and covered by golden tests.

### 3) Flux Artifact Provenance in Trace

### Command Surface

```bash
cub-scout trace <kind/name> -n <namespace> --artifacts [--format ascii|json|md]
```

### Required Data (when available)

- `artifact.url`
- `artifact.revision`
- `artifact.digest`
- `artifact.lastUpdateTime`
- `artifact.sourceKind` (`GitRepository|OCIRepository|HelmRepository|Bucket`)

### Acceptance Criteria

- If artifact metadata is missing/unreadable, output explicit `unknown` fields.
- Trace chain remains deterministic and backward-compatible without `--artifacts`.

### 4) Audit Timeline for GitOps Actions

### Command Surface

```bash
cub-scout map activity [--namespace <ns>] [--owner Flux|ArgoCD|Helm] [--since 24h] [--format ascii|json|md]
```

### Behavior

Normalize operational timeline entries from:

- Flux reconciliation conditions and status transitions
- Kubernetes warning/normal events for related workloads
- Deployment rollout progression events

### Required Output Fields

- `time`
- `source`
- `resource`
- `action`
- `result`
- `message`
- `suggestedNextStep`

### Acceptance Criteria

- Timeline sorted descending by time by default.
- Stable sorting for equal timestamps.
- Works in disconnected clusters with only Kubernetes events available.

### 5) Ephemeral PR Environment Detection (Gitea/Forgejo Aware)

### Command Surface

```bash
cub-scout map previews [--format ascii|json|md] [--stale-after 72h]
```

### Detection Heuristics (v0.20)

- Namespace/app labels or annotations containing:
  - `pull-request`, `pr-number`, `preview`
  - Forgejo/Gitea URL or repo hints
- Optional Flux source branch/tag conventions for PR refs

### Required Output Fields

- `previewID` (derived stable id)
- `repo`
- `prNumber`
- `namespaceOrTarget`
- `age`
- `stale` (bool)
- `cleanupSuggestion`

### Acceptance Criteria

- Deterministic heuristics with explainable match reason per preview.
- No provider lock-in assumptions required to produce output.
