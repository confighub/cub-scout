# v0.16.0 — Composition Attribution

**Tag:** `v0.16.0`
**Status:** Released
**Scope:** Deterministic ownership attribution across Crossplane and Kustomize

v0.16 introduces **composition attribution**: the ability to explain *who owns what* in a Kubernetes system, deterministically and reproducibly, using bundle-first reasoning.

This release adds **no inference, no guessing, and no replay-time computation**. All attribution is captured explicitly and replayed offline.

---

## Highlights

* **Attribution Graph (`attribution-graph.v1`)**

  * Explicit ownership and provenance modeled as a deterministic graph
  * Stable node and edge IDs, sorted output, no silent inference
* **Attribution Report (`attribution-report.v1`)**

  * Ranked, human-readable ownership explanations derived strictly from the graph
  * Deterministic scoring and tie-breaking
* **Debug Bundles with Attribution**

  * `debug --save-bundle` now persists real, replayable bundles
  * Attribution captured at bundle creation time
* **Crossplane Ownership**

  * XR ↔ MR ↔ Composition / CompositionRevision lineage
  * OwnerRef and label evidence handled explicitly
* **Kustomize Overlay Attribution (opt-in)**

  * `--kustomize <path>` records overlay ownership as a first-class fact
  * Clean precedence rules when Crossplane and Kustomize are both present
* **Offline Replay**

  * Attribution and reports replay deterministically with no cluster or git access

## New Schemas

### `attribution-graph.v1`

Models ownership and provenance as explicit facts.

**Node types**

* `xr`, `mr`, `claim`
* `composition`, `composition_revision`
* `k8s_object` (generic Kubernetes resources)
* `kustomize_overlay`

**Edge types**

* `owns`
* `selected_composition`
* `selected_composition_revision`

**Evidence**

* `owner_reference`
* `composite_label`
* `claim_label`
* `kustomize_overlay`
* `kustomize_origin` *(reserved for future use)*

---

### `attribution-report.v1`

Human-oriented explanation derived strictly from the attribution graph.

For each object:

* ownership status: **owned / unattributed / ambiguous**
* most relevant owner (if any)
* ranked candidate owners with reasons

**Ownership scoring (explicit and deterministic)**

| Evidence            | Score           |
| ------------------- | --------------- |
| `owner_reference`   | 100             |
| `kustomize_origin`  | 90 *(reserved)* |
| `composite_label`   | 80              |
| `kustomize_overlay` | 75              |
| `claim_label`       | 60              |

## CLI Additions

### Save a debug bundle

```bash
cub-scout debug deployment/api -n prod --save-bundle ./bundles
```

### Save a bundle with Kustomize attribution

```bash
cub-scout debug deployment/api -n prod \
  --save-bundle ./bundles \
  --kustomize ./overlays/prod
```

### Replay attribution

```bash
cub-scout bundle replay <bundle> --section attribution
cub-scout bundle replay <bundle> --section attribution-report
```

* Replay is offline, deterministic, and read-only
* ASCII output is always derived from JSON (`ASCII = f(JSON) + g`)

---

## Architectural Guarantees

All existing contracts remain true:

* Deterministic output everywhere
* Bundle-first reasoning (no recompute on replay)
* No new meaning without a new schema
* Unknowns are first-class (unattributed / ambiguous)
* No cluster or git access during replay
* No TUI-only semantics
