# v1.7.0 Release Notes

> **Status:** Released 2026-03-07.  
> Predecessor: `v1.1.0` (2026-02-25) documented in this folder.

**Theme:** *Platform scale and experimental meaning-first browse.*

This release closes the remaining v1.7 milestone scope:
- platform composition support beyond Crossplane (kro)
- experiment-track grouped browse surfaces
- hook compatibility verifier flow in scan/map
- connected summary + extensibility slices already merged in prior v1.7 PRs

---

## What's New

### Platform Composition: Crossplane + kro

`cub-scout` now supports kro as a first-class platform composition owner in addition to Crossplane.

Delivered:
- `kro` ownership detection (`kro.run/*`, owner references, API group detection)
- reverse trace owner mapping for kro
- kro lineage resolver:
  - managed resource -> kro instance -> optional ResourceGraphDefinition
- `trace` rendering for kro lineage
- `tree composition` now groups both Crossplane and kro roots
- owner filters/completions/docs updated to include `kro`

### Experimental Meaning-First Browse (`map meaning`)

New command:

```bash
cub-scout map meaning
```

Delivered:
- deterministic hybrid grouping (semantic + structural signals)
- comparative labels generated relative to sibling groups
- per-group evidence lines
- JSON + ASCII output for repeatable proofs
- bounded output controls (`--max-groups`, `--max-members`)

### Hook Compatibility Verifier Flow

Read-only lifecycle-hook compatibility verification is now part of the supported scan/map workflow:
- `scan --lifecycle-hazards`
- `map hooks`

Both surfaces are deterministic and read-only, with parser/classifier coverage and user-visible diagnostics.
