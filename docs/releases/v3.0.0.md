# v3.0.0 — Agentic GitOps observability, `cub scout landed`, and the `/v3` contract

> **Draft release notes — not yet tagged or published.**  
> The release before it is [v2.19.0](v2.19.0.md). Upgrade instructions and
> tested before/after commands are in [v3.0.0-migration.md](v3.0.0-migration.md).

`v3.0.0` completes the 3.0 contract transition, ships the first slice of
`cub scout landed` (CLI and standalone MCP tool `landed`) with bounded
read-only convergence waiting, and enforces declared byte ceilings and compact
summary views so agents and operators can budget every read.

Read [Breaking changes](#breaking-changes) and
[v3.0.0-migration.md](v3.0.0-migration.md) before upgrading.

---

## Highlights

### 1. `cub scout landed` — "did my change land?" (CLI + MCP)
- New command `cub scout landed <kind/name> -n <ns> --revision <sha>|--digest <sha256:...>|--unit-revision <rev>`
  and standalone MCP tool `landed` ([#998](https://github.com/confighub/cub-scout/pull/998),
  [#1001](https://github.com/confighub/cub-scout/pull/1001),
  [#1006](https://github.com/confighub/cub-scout/pull/1006)).
- Distinct states: `landed`, `converging` (with `convergence.recheckAfterSeconds`),
  `not-landed` (naming `brokenLink.stage`), and `not-observable`.
- Bounded, strictly read-only wait (`--wait`, default `0s`, CLI max `5m`,
  MCP max `60s`, poll interval `5s`, min `2s`) that returns as soon as the
  state leaves `converging` or the deadline expires.
- First slice covers Flux (`Kustomization`, `HelmRelease`, `GitRepository`,
  `OCIRepository`) and Argo CD (`Application`) delivering `Deployment`,
  `StatefulSet`, and `DaemonSet` workloads.
- Enforced zero false-landed invariant across 10 negative cases in unit tests
  and proven on real Flux and Argo CD deliveries in `CI/GitOps E2E`
  ([#1002](https://github.com/confighub/cub-scout/pull/1002)).

### 2. Cost an agent can count on (Package C)
- **Per-answer compact JSON byte ceilings enforced in CI** across all 10
  answer-bearing commands (`compare_source_truth`, `doctor`, `explain`,
  `gitops_settings`, `gitops_status`, `landed`, `map`, `release_check`,
  `scan`, `trace`) ([#996](https://github.com/confighub/cub-scout/pull/996),
  [#1001](https://github.com/confighub/cub-scout/pull/1001),
  [#1003](https://github.com/confighub/cub-scout/pull/1003)).
- **Deterministic bytes-and-tokens benchmark** across 24 prepared cluster
  cases published in [answer-sizes.md](../reference/answer-sizes.md)
  ([#997](https://github.com/confighub/cub-scout/pull/997)):
  - Raw Kubernetes objects across the 24 cases: **8,398,144 bytes** (~2,099,536 tokens).
  - Declared `cub-scout` `answer` ceilings for those 24 questions: **18,800 bytes** (~4,700 tokens) — a **99.78% reduction** in bytes read.
- **Compact `--view summary` for JSON and MCP** on `gitops settings`,
  `gitops status` ([#1005](https://github.com/confighub/cub-scout/pull/1005)),
  and `doctor` ([#1007](https://github.com/confighub/cub-scout/pull/1007)),
  preserving the exact `answer` block and top-level counts while omitting
  per-object detail lists.

### 3. Field value + revert prediction (A(2)), unrecorded-only comparison (A(3)), and agent field-manager convention (G5)
- **`explain --field-path <path>`** now emits live `value` / `valueFound` and
  `revertPrediction` (`likely-reverted`, `not-expected`, or `unknown`) grounded
  in observed Flux (`spec.suspend`) and Argo CD (`selfHeal`, `ignoreDifferences`)
  controller specs ([#1009](https://github.com/confighub/cub-scout/pull/1009),
  [#1011](https://github.com/confighub/cub-scout/pull/1011)).
- **`compare three-way --unrecorded-only`** (and MCP `unrecorded_only`) returns
  only unlinked or live-drifted resources while preserving full `summary` counts
  and `omissions[]` ([#1012](https://github.com/confighub/cub-scout/pull/1012)).
- **G5 field-manager convention** (`agent/<tool>[/<run>]`): strict parser and
  `KnownManagerTool` recognition as self-reported agent metadata without
  guessing on `kubectl-*` or controller strings
  ([#1004](https://github.com/confighub/cub-scout/pull/1004),
  [#1010](https://github.com/confighub/cub-scout/pull/1010)).

### 4. Plugin-first naming (`cub scout ...`)
- `cub scout ...` is now the documented primary invocation form across
  `README.md`, `CLI-GUIDE.md`, `start-here.md`, and `install.md`
  ([#994](https://github.com/confighub/cub-scout/pull/994)).
- The standalone `cub-scout` binary remains supported and ships alongside
  the plugin.

## Breaking changes

All removals completed their deprecation window in `v2.18.0`. Every removed
flag or command fails explicitly and names its replacement — none is silently
ignored. See [v3.0.0-migration.md](v3.0.0-migration.md) for tested before/after
examples ([#995](https://github.com/confighub/cub-scout/pull/995)).

- **Go module path moved to `/v3`** (`github.com/confighub/cub-scout/v3`)
  ([#991](https://github.com/confighub/cub-scout/pull/991)).
- **Removed 8 deprecated flags and commands** ([#992](https://github.com/confighub/cub-scout/pull/992)):
  - `trace --json`, `tree --json`, `graph export --json`, `gitops status --json` → use `--format json`.
  - `connect --go` → use `cub auth login` / `cub-scout setup`.
  - `app create --set-context` → use `cub context set` instead.
  - `hierarchy` → use `cub-scout map` / `cub-scout tree`.
  - `fleet outliers` → use `cub-scout map fleet`.
- **Verdict words removed from `compare source-truth` JSON and MCP output**
  (`status`, `source_truth`) ([#993](https://github.com/confighub/cub-scout/pull/993));
  read `answer.state` and `answer.reason` instead. ASCII and Markdown output
  and immutable `receipt/v1` payloads are unchanged.
- **Connected `cub` CLI version floor:** connected mode now requires
  `cub >= v0.11.4` (`pkg/hub.MinCubVersion`)
  ([#1000](https://github.com/confighub/cub-scout/pull/1000)).

## What was and was not verified

- **Verified on real clusters in CI (`CI/GitOps E2E`):**
  - `cub scout landed` positive (`landed`) and negative (`not-landed`) controls
    on real Flux (`deployment/cart -n boutique`) and real Argo CD
    (`deployment/guestbook-ui -n guestbook`) deliveries (`scripts/ci/landed-lane.sh`,
    [#1002](https://github.com/confighub/cub-scout/pull/1002)).
  - Existing Flux, Argo CD, Sveltos, Helm, kro, Crossplane, Terraform, and
    `release check` lanes remain green.
- **Verified deterministically without a live cluster:**
  - All 15 before/after migration command pairs executed against the built
    binary (`test/unit/migration_3_0_commands_test.go`, [#995](https://github.com/confighub/cub-scout/pull/995)).
  - All 10 answer-bearing commands enforced for CLI/MCP answer parity and
    compact JSON byte ceilings (`answer_size_ceilings_test.go`,
    `trace_surface_conformance_test.go`).
  - 19 deterministic `landed` unit subtests (8 recorded fixtures + 10-case
    zero false-landed invariant + bounded wait timing).
- **Not yet verified / deferred beyond 3.0:**
  - `cub scout landed` for Sveltos, kro, Crossplane, Helm, and Modelplane
    returns `not-observable` / `unsupported-controller` in 3.0; parity is
    planned for 3.2 ([vision-3.x.md](../proposals/vision-3.x.md)).
  - `cub scout landed` `converging` state and `--wait` convergence loop are
    covered by deterministic unit tests, not yet by a live mid-rollout race
    test in CI.
  - Paid model-in-the-loop evals (rungs 2–3) were not run.
