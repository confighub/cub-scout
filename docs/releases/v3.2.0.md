# v3.2.0 — Real-cluster Argo Rollouts proof, live blast-radius, CI gate, and offline fleet receipts (Draft)

> **Draft — not yet tagged or published.** The latest published release remains
> [v3.1.0](v3.1.0.md) (`084a9e5f`, 2026-11-26). This draft tracks merged Wave 4
> work on `main` and in-progress Wave 5 items ahead of the `v3.2.0` cut.

`v3.2.0` extends the strictly read-only `v3.1.0` write loop to **real-cluster
Argo Rollouts CI proof**, **live-cluster bounded `graph blast-radius`**, a
**reusable CI promotion gate and ops-bot consumer contract**, **offline
multi-cluster `receipt verify-fleet` aggregation**, and **standing 3.x release
benchmarks & Krew packaging** — without adding a single cluster write or a
single unapproved `answer.state` word.

---

## Highlights (Merged on `main` — Wave 4)

### 1. Real-cluster Argo Rollouts `v1.8.3` CI lane & live `graph blast-radius` ([#1037](https://github.com/confighub/cub-scout/pull/1037), Refs `#596`, `#645`)
- Added `scripts/ci/rollouts-lane.sh`, wired into `CI / GitOps E2E` in
  `.github/workflows/ci.yaml`, installing SHA-256-verified Argo Rollouts
  `v1.8.3` on a disposable cluster and proving
  `cub-scout landed ro/lane-web --verify-pod-images` against live controller
  status and running Pod `imageID` digests:
  - Healthy `Rollout` + matching Pod digest → `landed` (`pod-images` basis,
    `requestsMade > 0`)
  - Mismatched `--image` → `not-landed` (`workload-failed` / `workload`)
  - Canary pause patch (`status.phase == Paused`) → `converging`
    (`workload-rolling-out`)
- Extended `cub-scout graph blast-radius` with strictly read-only, bounded
  live-namespace reads and explicit `--kube-context` selection (rejecting
  `--kube-context` combined with `--recording`), reusing sanitization to strip
  `Secret.data`/`stringData`, `ConfigMap.data`/`binaryData`, and sensitive Pod
  fields.

### 2. Reusable CI promotion gate & ops-bot consumer contract ([#1034](https://github.com/confighub/cub-scout/pull/1034), Refs `#596`, `#645`)
- Added `examples/ci-gates/verify-landed/`:
  - Composite GitHub Action (`action.yml`), runner (`verify-landed.sh`),
    staging-to-prod example workflow (`workflow-example.yaml`), and offline
    test harness (`test_verify_landed.sh`).
  - Supports optional `before-write`, `landed --verify-pod-images` (with
    `--revision`, `--digest`, or `--unit-revision`), optional Ed25519
    `receipt sign`/`verify`, offline `--recording`, and fail-closed exit when
    `answer.state != "landed"` or signature verification fails.
- Added `examples/bot/consumer-contract.md` defining the wire contract for
  external ops bots (`k8sbot`, Pilot, incident/Slack bots) consuming `bot` and
  `watch` JSONL/webhook `answer` envelopes without cluster API access, backed by
  deterministic tests (`bot_consumer_contract_test.go`,
  `ci_gate_and_bot_contract_test.go`).

### 3. Offline multi-cluster `cub-scout receipt verify-fleet` ([#1035](https://github.com/confighub/cub-scout/pull/1035), Refs `#889`, `#645`)
- New strictly offline command:
  ```bash
  cub-scout receipt verify-fleet \
    --inputs <files-or-dirs> \
    --pubkey <pub.pem> \
    [--revision <sha-or-digest>] \
    [--require-clusters dev,staging,prod] \
    [--max-age 30m] \
    [--format ascii|json]
  ```
- Verifies Ed25519 signatures across local `signed-receipt/v1` JSON files and
  aggregates per-cluster landing state, `observedAt`, and staleness into one
  `fleet-receipt-verification/v1` output with standard `answer` envelope.
- Fails closed (non-zero exit) on any invalid signature, tampered payload,
  wrong key, malformed JSON, revision mismatch, missing required cluster, or
  non-landed cluster state; zero network calls, zero Kubernetes calls, zero
  fleet database.

### 4. `v3.1.0` Krew checksums, standing 3.x benchmarks & roadmap refresh ([#1036](https://github.com/confighub/cub-scout/pull/1036), Refs `#645`)
- Stamped `dist/krew/cub-scout.yaml` for published `v3.1.0` with official
  SHA-256 digests and release download URIs (`linux/{amd64,arm64}` and
  `darwin/{amd64,arm64}`).
- Added the `v3.1.0` standing benchmark section to
  [docs/reference/answer-sizes.md](../reference/answer-sizes.md):
  - All 13 CI-enforced `answer` block ceilings total **9,302 bytes** (~2,326
    tokens), including `before_write` (672B), `bot` (624B), and `watch` (609B),
    each `<= 700B`.
  - 4-case offline `graph blast-radius` benchmark: **54,534 raw bytes → 9,279
    blast-radius JSON bytes (82.98% overall reduction; 89.65% on 4-hop Flux;
    4-hop compact JSON 1,084B `<= 1,200B`)**.
- Refreshed [docs/proposals/vision-3.x.md](../proposals/vision-3.x.md) to
  separate published `v3.1.0` capabilities from remaining 3.2–3.5 work.
