# v3.2.0 — Real-cluster Argo Rollouts proof, live blast-radius MCP, CI gate, and offline fleet receipts

**Published on 2026-11-27.** The release before it is [v3.1.0](v3.1.0.md).

`v3.2.0` extends the strictly read-only `v3.1.0` agent write loop with
**real-cluster Argo Rollouts `v1.8.3` CI proof**, **live-cluster bounded
`graph blast-radius` (CLI, `before-write --include-blast-radius`, and MCP
`graph_blast_radius`)**, a **reusable GitHub Actions CI promotion gate and
ops-bot consumer contract**, **offline multi-cluster `receipt verify-fleet`
aggregation with a runnable 4-cluster example**, **offline in-toto Statement v1
attestation export (`receipt export-attestation`)**, and the **`cub mini`
read-only hook contract** — without adding a single cluster write or a single
unapproved `answer.state` word.

---

## Highlights

### 1. Real-cluster Argo Rollouts `v1.8.3` CI lane & live `graph blast-radius` ([#1037](https://github.com/confighub/cub-scout/pull/1037), Refs `#596`, `#645`)
- Added `scripts/ci/rollouts-lane.sh`, wired into `CI / GitOps E2E` in
  `.github/workflows/ci.yaml`, installing SHA-256-verified Argo Rollouts
  `v1.8.3` on a disposable cluster and proving
  `cub-scout landed ro/lane-web --verify-pod-images` against live controller
  status and running Pod `imageID` digests:
  - Healthy `Rollout` + matching Pod digest → `landed` (`pod-images` basis,
    `requestsMade > 0`)
  - Mismatched `--image` → `not-landed` (`workload-failed` / `workload`)
  - Canary pause patch (`status.phase == Paused`) → `converging`
    (`workload-rolling-out`)
- Extended `cub-scout graph blast-radius` with strictly read-only, bounded
  live-namespace reads and explicit `--kube-context` selection (rejecting
  `--kube-context` combined with `--recording`), reusing sanitization to strip
  `Secret.data`/`stringData`, `ConfigMap.data`/`binaryData`, and sensitive Pod
  fields.

### 2. Pre-write blast-radius summary & read-only MCP `graph_blast_radius` ([#1041](https://github.com/confighub/cub-scout/pull/1041), Refs `#596`, `#645`)
- Added optional `--include-blast-radius` to `cub-scout before-write` (CLI and
  MCP `before_write`, live and `--recording`), embedding a bounded `blastRadius`
  summary (`affectedWorkloadsCount`, `affectedWorkloads` capped at 5 refs,
  `truncated`) while keeping `before_write`'s `answer` block within its
  `<= 700B` ceiling.
- Exposed strictly read-only MCP tool `graph_blast_radius` (`target`,
  `namespace`, optional `kube_context`, optional `recording`) with
  `structuredContent`, keeping all MCP catalog and core-profile ceilings green.

### 3. Reusable CI promotion gate & ops-bot consumer contract ([#1034](https://github.com/confighub/cub-scout/pull/1034), Refs `#596`, `#645`)
- Added `examples/ci-gates/verify-landed/`:
  - Composite GitHub Action (`action.yml`), runner (`verify-landed.sh`),
    staging-to-prod example workflow (`workflow-example.yaml`), and offline
    test harness (`test_verify_landed.sh`).
  - Supports optional `before-write`, `landed --verify-pod-images` (with
    `--revision`, `--digest`, or `--unit-revision`), optional Ed25519
    `receipt sign`/`verify`, offline `--recording`, and fail-closed exit when
    `answer.state != "landed"` or signature verification fails.
- Added `examples/bot/consumer-contract.md` defining the wire contract for
  external ops bots (`k8sbot`, Pilot, incident/Slack bots) consuming `bot` and
  `watch` JSONL/webhook `answer` envelopes without cluster API access, backed by
  deterministic tests (`bot_consumer_contract_test.go`,
  `ci_gate_and_bot_contract_test.go`).

### 4. Offline multi-cluster `cub-scout receipt verify-fleet` & runnable 4-cluster example ([#1035](https://github.com/confighub/cub-scout/pull/1035), [#1040](https://github.com/confighub/cub-scout/pull/1040), Refs `#889`, `#645`)
- New strictly offline command:
  ```bash
  cub-scout receipt verify-fleet \
    --inputs <files-or-dirs> \
    --pubkey <pub.pem> \
    [--revision <sha-or-digest>] \
    [--require-clusters dev,staging,prod-east,prod-west] \
    [--max-age 30m] \
    [--format ascii|json]
  ```
- Verifies Ed25519 signatures across local `signed-receipt/v1` JSON files and
  aggregates per-cluster landing state, `observedAt`, and staleness into one
  `fleet-receipt-verification/v1` output with standard `answer` envelope
  (`<= 700B`), failing closed on any tampered payload, wrong key, revision
  mismatch, missing required cluster, or non-landed cluster state.
- Added self-contained 4-cluster example in
  [examples/fleet-promotion-proof/](../../examples/fleet-promotion-proof/)
  (`verify.sh`, test-only `test-pub.pem`, 4 signed receipts, zero private key
  material), [docs/howto/fleet-promotion-proof.md](../howto/fleet-promotion-proof.md),
  and `test/unit/fleet_promotion_example_test.go`.

### 5. Offline in-toto v1 attestation export (`receipt export-attestation`) ([#1038](https://github.com/confighub/cub-scout/pull/1038), Refs `#889`, `#600`, `#645`)
- Added strictly offline `cub-scout receipt export-attestation --input <file|-> [--pubkey <pub.pem>] [--cluster <name>] [--target <slug>] [--release <id>] [-o <out.json>]`.
- Verifies Ed25519 signature and canonical `payloadDigest` when `--pubkey` is
  supplied (failing closed with exit 1 and no output on tamper/wrong key) and
  emits a deterministic **in-toto Statement v1**
  (`https://confighub.com/attestations/landed/v1`) ready for ConfigHub `G4`
  `ChangeWorkflow` attestations or `cosign` once upstream `D6` lands.

### 6. `cub mini` hook contract, Krew packaging & standing benchmarks ([#1036](https://github.com/confighub/cub-scout/pull/1036), [#1039](https://github.com/confighub/cub-scout/pull/1039), Refs `#645`)
- Added [docs/howto/cub-mini-integration.md](../howto/cub-mini-integration.md)
  defining the clean read-only witness vs write-owner boundary between
  `cub mini` / agent skills and `cub-scout`.
- Updated [docs/reference/answer-sizes.md](../reference/answer-sizes.md) with
  all 13 CI-enforced `answer` block ceilings (9,302 bytes total) and the
  4-case `graph blast-radius` benchmark (54,534 → 9,279 bytes, 82.98%
  reduction; 89.65% on 4-hop Flux).
- Stamped `dist/krew/cub-scout.yaml` with verified SHA-256 digests and
  refreshed [docs/proposals/vision-3.x.md](../proposals/vision-3.x.md).
