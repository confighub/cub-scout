**Release Date:** 2026-02-05

## Overview

v0.19.1 is a **trust and clarity** release. While v0.19 delivered TUI polish and behavioral locking, v0.19.1 ensures that a new user's first hour with cub-scout is honest, predictable, and confidence-building.

This release addresses 7 UX issues discovered during comprehensive new-user testing ("Ralph Mode"), plus 2 additional low-priority items filed for future work.

---

## What Changed

### Phase 1 — Trust Repairs (High Priority)

#### 1. Trace Command Now Correctly Shows Healthy Resources (#107)

**Before:** Healthy Flux resources displayed red X with misleading "Chain broken" messages.

```
✗ GitRepository/podinfo           # Red X for HEALTHY resource!
  │ Error: stored artifact for revision '6.5.0@sha1:2cbe0fc...'
```

**After:** Ownership indicators like "Managed by Flux" correctly show green checkmarks.

```
✓ GitRepository/podinfo
  │ Status: stored artifact for revision '6.5.0@sha1:2cbe0fc...'
```

**Technical Change:** Updated `isReadyStatus()` in `pkg/agent/flux_trace.go` to recognize:
- "managed by" — ownership confirmed (positive)
- "fetched" — artifact retrieved (positive)
- "health check passed" — explicit health (positive)

---

#### 2. Status Command Warns About Expired Auth Tokens (#108)

**Before:** Status showed green "Connected" even with expired tokens, causing confusing failures later.

```
ConfigHub:  ● Connected    # Looks good!
...
Error: create app space: exit status 1  # Fails with no explanation
```

**After:** Status validates auth and shows clear warning with remediation.

```
ConfigHub:  ● Connected (auth expired) (user@example.com)
            ⚠ Token expired or invalid
            Run: cub auth login
```

**Technical Change:** Added `validateAuthToken()` function in `cmd/cub-scout/status.go` that checks `cub auth get-token` and introduces explicit "auth_expired" mode.

---

#### 3. Demos Check Prerequisites Before Running (#106)

**Before:** Demos silently degraded without GitOps CRDs, showing only "Native" resources.

```
$ ./cub-scout demo quick
# Shows "By Owner: Native(22)" instead of Flux/ArgoCD
# No indication of what went wrong
```

**After:** Demos check for required CRDs and provide helpful guidance.

```
⚠ Demo prerequisites not met

Missing:
  • Flux CRDs (GitRepository, Kustomization)
  • ArgoCD CRDs (Application)

To install:
  $ flux install
  $ kubectl apply -n argocd -f https://...

Alternatives:
  • Run 'cub-scout demo ccve' (no CRDs required)
  • See docs/getting-started/first-map.md for setup
```

**Technical Change:** Added `checkDemoPrerequisites()` function in `cmd/cub-scout/demo.go` with `hasFluxCRDs()` and `hasArgoCRDs()` checks. Each demo now declares its requirements via `RequiresCRDs` field.

---

### Phase 2 — Demo Honesty (Medium Priority)

#### 4. CCVE Demo Now Properly Detects Vulnerabilities (#109)

**Before:** Demo reported "No issues found" due to container name mismatch.

```
$ ./cub-scout demo ccve
Step 2: Running CCVE scan...
✓ No issues found    # Should detect CCVE-2025-0027!
```

**After:** CCVE-2025-0027 is correctly detected.

```
CRITICAL (1)
────────────────────────────────────────────────────────────────────
[C] Grafana sidecar namespace whitespace [CCVE-2025-0027]
  Resource: monitoring/Deployment/grafana
  Message: NAMESPACE env var contains whitespace after comma...
  → Remediation: Remove spaces from comma-separated namespace list
```

**Technical Change:** Changed sidecar container name from `grafana-sc-dashboard` to `grafana-sidecar` in `examples/impressive-demo/bad-configs/monitoring-bad.yaml` to match the detection pattern.

---

#### 5. Import Errors Now Show Root Cause (#112)

**Before:** Generic errors obscured actionable information.

```
Creating App Space: my-space... ✗
Error: create space: exit status 1
```

**After:** Errors include root cause and remediation hints.

```
Creating App Space: my-space... ✗
Error: unauthorized: token expired

→ Hint: Your ConfigHub token may be expired.
  Run: cub auth login
```

**Technical Change:** Added `formatCubError()` helper in `cmd/cub-scout/import.go` that detects:
- Auth issues (401, unauthorized, token, expired) → suggests `cub auth login`
- Network issues (connection refused, no such host) → suggests checking connectivity
- Permission issues (403, forbidden) → suggests checking space access

### Phase 3 — Paper Cuts (Low Priority)

#### 6. Demo Help Text Now Matches Actual Commands (#110)

**Before:** Help showed `--list` flag but actual command was `demo list`.

```
$ ./cub-scout demo --help
Examples:
  cub-scout demo --list     # WRONG

$ ./cub-scout demo --list
Error: unknown flag: --list
```

**After:** Help text correctly shows subcommand syntax.

```
$ ./cub-scout demo --help
Examples:
  cub-scout demo list       # CORRECT
```

**Technical Change:** Updated all references in:
- `cmd/cub-scout/demo.go`
- `CLI-GUIDE.md`
- `examples/demos/README.md`
- `examples/demos/walkthrough.md`
- `examples/impressive-demo/DEMO-SCRIPT.md`

---

#### 7. Invalid --owner Flag Now Shows Valid Options (#111)

**Before:** Invalid owner values silently returned empty results.

```
$ ./cub-scout map list --owner typo
# Empty output, no error
```

**After:** Invalid values trigger helpful error with valid options.

```
$ ./cub-scout map list --owner typo
Error: invalid owner "typo" (valid: Flux, ArgoCD, Helm, ConfigHub, Crossplane, Terraform, Native)
```

**Technical Change:** Added `ValidateOwner()` calls in:
- `runMapList()` in `cmd/cub-scout/map.go`
- `runLocalClusterTUI()` in `cmd/cub-scout/localcluster.go`

Also normalizes case (e.g., "flux" → "Flux") for user convenience.

## Guiding Principles Applied

v0.19.1 followed these rules throughout:

1. **Never show green for broken states** — Status now validates auth
2. **Never show red for healthy systems** — Trace fixed for ownership indicators
3. **Demos must fail clearly or succeed meaningfully** — Prerequisite checks added
4. **Errors must explain why, not just what** — formatCubError() with hints
5. **Guidance should help, not intimidate** — Friendly error messages with next steps
