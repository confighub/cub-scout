# v2.3.1 Release Notes — Install/Object-Set Receipts

> **Status:** Draft release notes. This file describes what the `v2.3.1`
> tag will ship when cut from `main`.
>
> **Previous release:** [`v2.3.0`](v2.3.0.md) — attribution, receipts, and
> AI-agent skills.

**Theme:** *prove rendered install object sets landed correctly.* This is a
small additive release on top of `v2.3.0`: it adds an install-level receipt
predicate, documents the Helm experiment verification story, and tightens
receipt/proof vocabulary.

There are **no breaking changes**. Existing receipt predicates, JSON
contracts, command names, and exit codes remain compatible.

## What's In This Patch

### Install/object-set receipt verification

`receipt verify` now supports rendered manifest sets:

```bash
cub-scout receipt verify \
  --file out/manifests \
  --scope namespace/example \
  --format json \
  --out install.object-set.receipt.json \
  --fail-on any-non-pass
```

This selects the new `object-set-matches` predicate and emits an in-toto
Statement v1 receipt with two object-set subjects:

- `rendered-object-set://sha256/<id>` for the desired YAML set
- `k8s-live-object-set://namespace/<ns>` or `k8s-live-object-set://cluster`
  for the observed live projection

PASS means every desired object identity from the rendered YAML is present live
and every authored field still matches. Kubernetes server-added map fields and
`status` are outside the claim. Missing objects or changed authored fields
produce BLOCK. API mapping or live-read gaps produce INCONCLUSIVE.

The receipt deliberately includes `extra-live-object-coverage`: cub-scout
proves the desired set is present and matching, but does not yet prove that no
extra live objects exist outside that desired identity set.

### Helm experiment verification example

New example:
[`examples/helm-expt/`](../../examples/helm-expt/)

The example explains how cub-scout complements:

- `confighub/helm-expt`: Helm render == `cub install` render
- `confighub/installer`: package/spec -> rendered objects -> ConfigHub
  Units/OCI
- cub-scout: rendered objects are present and matching in the live cluster

The runbook is chart/release-oriented. Redis is included as the first worked
value set, not as the whole shape of the example.

### Receipt/proof vocabulary

New concept reference:
[`docs/concepts/receipts-and-proofs.md`](../concepts/receipts-and-proofs.md)

The docs now separate:

- a **claim**: what is being asserted
- **evidence**: what cub-scout observed
- a **receipt**: the fingerprinted in-toto artifact
- a **proof chain**: adjacent receipts/artifacts that together support an
  operator decision

## Behavior

### What changes

- New predicate: `object-set-matches`
- New `receipt verify --file <manifest.yaml|dir>` mode for rendered object
  sets
- New object-set subject schemes:
  `rendered-object-set://sha256/<id>` and
  `k8s-live-object-set://namespace/<ns>` / `k8s-live-object-set://cluster`
- New object-set evidence summary in JSON and ASCII receipt rendering
- New omission entries: `object-set-coverage` and
  `extra-live-object-coverage`

### What does not change

- Existing receipt predicates:
  `applied-matches-spec`, `source-truth-pass`, `no-manual-edits-since`, and
  `aggregate-verdict`
- Existing single-resource and aggregate receipt behavior
- Existing `watch --emit-receipt-on` behavior
- Existing CLI exit codes and read-only invariants
- Existing ConfigHub connected-mode behavior

## Upgrade / Install


