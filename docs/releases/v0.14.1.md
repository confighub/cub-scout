# v0.14.1 Release Notes

**Release Date:** 2026-02-03

## Summary

v0.14.1 adds comprehensive GitOps apply observability with the `gitops status` command, enabling users to immediately see where and why GitOps pipelines are failing.

## New Features

### `gitops status` Command

Show the health of your GitOps pipeline:

```bash
cub-scout gitops status           # All namespaces
cub-scout gitops status -n flux-system  # Specific namespace
cub-scout gitops status --json    # Machine-readable
```

Output includes:
- **Backend** — Detected GitOps tool (Flux, ArgoCD, Worker, none)
- **Transport** — Manifest delivery method (OCI, Git, Helm)
- **Sources** — Source resources with health and failure details
- **Deployers** — Deployer resources with stage classification
- **Next Steps** — Actionable guidance for failures

### Failure Stage Classification

When deployments fail, `gitops status` identifies which stage failed:

| Stage | Description |
|-------|-------------|
| `source` | OCI/Git/Helm fetch failed (auth, network, not found) |
| `build` | Kustomize/Helm rendering failed |
| `apply` | Kubernetes apply failed (validation, RBAC) |
| `sync` | ArgoCD sync failed |
| `healthy` | All stages passed |

### Backend Detection

Automatically detects which GitOps backend manages your cluster:

| Backend | Detection |
|---------|-----------|
| `flux` | Kustomization or HelmRelease CRDs present |
| `argocd` | Application CRD present |
| `worker` | ConfigHub worker labels on resources |
| `none` | No GitOps backend detected |
