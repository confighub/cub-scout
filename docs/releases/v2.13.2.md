# v2.13.2 — Correct provenance and health for Flux and Argo CD, with or without their CLIs

**Prepared, not published.** This page describes the candidate on `main`. It
becomes a release when the maintainer tags it; the publication record and
archive verification are added then.

This is a correction release cut from `main`. It also carries the opt-in work
merged towards v2.14 since v2.13.1, which is listed separately below and is
still labelled "2.14 candidate" in the reference docs.

## Corrections

Upgrade for these. Each was found by running cub-scout against a real cluster
and comparing its surfaces with each other; each has a test built on output
recorded from that cluster.

- **A receipt could name the wrong Git repository.** For a workload delivered
  by Flux, the Git source was taken from a trace of the workload's owning
  Kustomization or HelmRelease. Under a parent Kustomization, which is how
  `flux bootstrap` lays a cluster out, that is the parent's fleet repository.
  `receipt verify`, watch-built receipts and the session path of `compare`
  reported it as the workload's source, and a receipt could pass
  `applied-matches-spec` against it. Under a root Kustomization there was no
  source at all. The workload itself is traced now. **Receipts issued by
  earlier versions for workloads under a parent Kustomization may name the
  wrong repository; nothing finds or flags them.**
- **A failing Flux delivery could be drawn as healthy.** With the `flux` CLI
  installed, `trace` showed a Kustomization whose build was failing with a
  green tick, because `flux trace` prints the same status line for a failing
  object as for a healthy one. Readiness now comes from each object's `Ready`
  condition.
- **`explain` said nothing about a failing delivery chain.** A workload still
  running its last good revision under a failing Kustomization or a degraded
  Application was reported as healthy. `health` now adds
  `; delivery not ready at <Kind>/<name>` and a note gives the reason.
- **`map status` treated a workload scaled to zero as a problem** and exited 1,
  while `map list` showed the same object as Ready. `map issues`, `map
  workloads` and `map dashboard` shared the defect.
- **`suggest-remedy` ran `kubectl` through a shell.** It built a command line by
  string interpolation, so a kind, name or namespace containing shell syntax
  was interpreted by the shell. Arguments are now passed as a vector and values
  that are not valid Kubernetes identifiers are rejected. v2.13.1 and earlier
  2.x releases contain the old code. Reaching it needs a finding database in
  `./cve/ccve` under the working directory or beside the binary; the release
  archives contain only the binaries, the README and the licence.
- **`compare` was silent when it found no source** for a GitOps-owned workload
  on its default path. It now records why in the result's notes.

## Works without the `flux` and `argocd` CLIs

Both CLIs are optional, and an agent's sandbox or a CI job often has neither.

- Without the `argocd` CLI, `explain`, `receipt verify` and `compare` could not
  name an Argo CD source that `trace` could. They now read the Application
  through the Kubernetes API, as `trace` does.
- Without the `flux` CLI, no command could say where a Flux-delivered workload
  came from. A Kubernetes-API tracer now follows the same objects `flux trace`
  reads, with exact `get` reads: the workload's Flux labels, its Kustomization
  or HelmRelease, and that object's GitRepository, OCIRepository or
  HelmRepository. The reader needs `get` on those kinds.

With either CLI installed it is used as before.

## Explicit context selection

`--kube-context` now covers nearly every command that reads a cluster. New in
this release: all 21 cluster-reading `map` subcommands, `tree`, `graph export`,
`graph explain`, `snapshot`, `watch`, `bot`, `debug`, `drift`,
`patterns detect`, `patterns explain`, `context-pack`, `receipt verify` and
`compare <resource>`. The selection is resolved once, every read in the command
uses it, and the kubeconfig is not modified. A missing or blank selection is
refused; nothing falls back to the ambient context. Printed cluster labels
come from the same selection.

For `receipt verify` and watch-built receipts the selection also covers the
tracers behind their controller and Git evidence. Before this release
`watch --kube-context` bound its own reads while its receipts took Git evidence
from the ambient cluster.

Not covered yet: `suggest-remedy`, `quickstart`, the `hierarchy` TUI, and
trace's child clients (#812, #746). `compare` with no resource refuses the flag.

## Behaviour changes to expect

- `trace` prints `Ready`, `Not ready`, `Suspended` or `Unknown` for a Flux
  object where it printed `Last reconciled at <time>`.
- `explain`'s `health` string and `notes` change when a delivery link reports
  that it is not ready.
- `map status` exits 0 where it exited 1 for a workload scaled to zero.
- `compare <resource>` may add a "LIVE enrichment incomplete" note.
- `suggest-remedy --namespace` rejects a value that is not a valid namespace
  name.
- A receipt for a Flux-delivered workload under a root Kustomization now
  carries a Git source and can pass `applied-matches-spec`; it was INCONCLUSIVE.
- Tracing a Flux chain makes one extra `get` per Flux object in it.

## What was and was not verified

Verified at `23ddcaa2`, the candidate:

- required CI on `main`: Unit Tests, Integration Tests, GitOps E2E and Proof
  Artifact;
- for each correction, a deterministic test on recorded real output, a check
  that the test fails without the fix, and a before/after run on a disposable
  cluster (in each pull request);
- retained live harnesses under
  [examples/source-agreement](../../examples/source-agreement/): ten surfaces
  name the same source on real Flux and real Argo CD, in root and parent
  layouts, with and without each CLI.

Not verified, and not claimed:

- Full Verification, Connected E2E, Demo Tests and Windows did not run on any
  change in this release; the private scanner lane has no credential.
- No agent eval was added or run. This release makes no claim that cub-scout
  saves an agent time or cost, and none about agent answer quality.
- No ConfigHub-connected run exercised the changed paths.
- The Flux API tracer's Bucket and `spec.chartRef` paths, and a ConfigHub OCI
  source, were not exercised.
- The tagged build, archives, checksums, Homebrew formula and public Go proxy
  install are checked at publication, not before.
