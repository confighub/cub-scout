# v2.13.3 — See every Argo CD and Flux deployer's sync settings in one place

**Published 2026-10-09.** [Release and assets](https://github.com/confighub/cub-scout/releases/tag/v2.13.3)
at source `88163206b42842adb72f40842ba2e36554ebb173`. The
[tagged tests and packaging run](https://github.com/confighub/cub-scout/actions/runs/37909653349)
passed. What was checked on the published artifacts is under
[Publication checks](#publication-checks).

This is a small additive release. It adds one read-only command and changes no
existing command's behaviour, except that `map deep-dive` prints one more
section. If you do not need the new command there is no reason to upgrade from
v2.13.2.

## New: `gitops settings` (preview)

Every GitOps deployer carries settings that decide what it does without being
asked: whether it syncs on its own, whether it reverts a manual change, whether
it deletes what leaves the source, and which apply options it uses. They are
written per object. `gitops settings` reads them all and inverts them: for each
setting, which deployers have which value.

```bash
cub scout gitops settings                          # as a cub plugin
./cub-scout gitops settings                        # standalone
./cub-scout gitops settings --setting self-heal=off
./cub-scout gitops settings --project payments --format md
```

| Kind | Reported |
|---|---|
| Argo CD `Application` | `auto-sync`, `self-heal`, `prune`; every sync option with its value; `automated.allowEmpty`; `ignoreDifferences` |
| Flux `Kustomization` | `suspend`, `prune`, `force`, `wait`; `deletionPolicy` when declared |
| Flux `HelmRelease` | `suspend`, `driftDetection.mode`; `driftDetection.ignore`; every declared scalar under `install`, `upgrade`, `rollback`, `uninstall`, `test` |

- Argo CD Applications are grouped by project; Flux objects, which have no
  project, by namespace. `--group-by setting` and `--group-by deployer` give the
  other two views.
- `--setting name[=value]` (repeatable), `--project` and `-n` select.
- `--format ascii|json|md`, `--tui` and `--kube-context` work as they do for
  `gitops status`. Markdown links each Application to the Argo CD UI.
- `map deep-dive` prints the default view as a Delivery Settings section.

What it is careful about:

- **Absent is unset, not off.** A field that is absent is shown as `unset` with
  the controller's documented default beside it, and counted under that default
  with an `(unset)` mark. For an Application that syncs manually, `self-heal`
  and `prune` are `n/a`.
- **Not read is not absent.** Every list is reported under Reads. A kind the
  caller may not list is `NOT READ`, and the output is marked incomplete; it is
  not shown as a cluster with none. The exit code is still 0.
- **No invented links.** An Application links to the Argo CD UI only when
  `argocd-cm` in its own namespace declares a `url`.
- **Options are passed through** under the controller's own names, including
  ones this release has never heard of.

What it is not:

- It reports what each `spec` declares. It does not show that a controller
  acted on a setting, and it does not judge whether a setting is acceptable.
- The same facts are available from `kubectl get applications -o json` and a
  filter. This command reads them once across both controllers and handles the
  cases above the same way every time.
- **Preview:** the JSON shape is documented in the
  [JSON contract](../reference/json-contracts.md#delivery-settings-contract)
  and may still change. There is no MCP tool for it yet.

See the [command reference](../reference/commands.md#gitops-settings) and the
[example](../../examples/delivery-settings/).

## Behaviour changes to expect

- `map deep-dive` prints a Delivery Settings section before Workloads. It makes
  three more list calls and one `get` of `argocd-cm` per namespace that holds
  an Application.
- Nothing else changes.

## What was and was not verified

Verified before publication:

- required CI on `main` at the tagged commit `88163206`: Unit Tests,
  Integration Tests, GitOps E2E and Proof Artifact; and a clean local build,
  `go vet ./...` and `go test ./...` on that commit;
- deterministic tests, including one over objects recorded unedited from a real
  API server, and 24 mutation checks, each caught by a named test;
- a retained run on a disposable kind cluster with real Argo CD v3.5.3 and Flux
  ([proof](../../examples/delivery-settings/live-proof.json)), including two
  restricted service accounts: one that may not list Applications, and one that
  may not read ConfigMaps;
- an independent review of the change, including a check of each named
  controller default against the upstream Argo CD and Flux sources;
- the full CI level, dispatched once on the tree that became `f1db8c45`
  ([run 37902545764](https://github.com/confighub/cub-scout/actions/runs/37902545764)):
  Windows Release Runtime on amd64 and arm64 and Connected E2E passed. This is
  the first run of those lanes on the code merged since v2.13.1.

Not verified, and not claimed:

- **No agent eval was added or run.** This release makes no claim that
  `gitops settings` saves an agent time or cost.
- The `--tui` viewport was tested on its content, not exercised in a terminal.
- ApplicationSet-generated Applications and older Flux API versions are
  unit-tested only. Sveltos, AppProject-imposed settings and per-resource
  annotations are not covered.
- **Full Verification and most of Demo Tests did not run.** In the same full
  run both stopped at provisioning the private scanner, which needs a
  credential the repository does not have (#774). Full Verification ran no
  test; Demo Tests ran the quick demo, which passed, and skipped the ccve,
  query and scenario demos.
