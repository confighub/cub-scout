## Scope

- Resource-backed intended Kubernetes configuration through MCP
  `confighub_k8s_resources` and `confighub_k8s_types` (`#516`).
- Generic ConfigHub Resource-index queries through MCP `confighub_resources`
  (`#517`), with explicit space scope and server-side predicates.
- Supporting ConfigHub live-status evidence on Argo Application activity rows
  (`#518` / `#520`). Require observed Application Space ID matching the
  reported Space ID plus a unique exact Application name. Missing/conflicting
  metadata or ambiguous names/statuses produce correlation omissions.
- Fixed namespace-scoped MCP `map` calls: the adapter now sends the supported
  `--namespace` flag rather than the unsupported `-n` shorthand.
- Fixed bot image startup under `runAsNonRoot`: the container now declares
  numeric UID/GID `65532:65532`, the base image's existing nonroot account.
  Kubernetes rejected the previous named user before the bot could start.

These additions preserve existing command, JSON, MCP, and receipt contracts.
ConfigHub Resource rows describe stored intended configuration; they do not
establish live health, drift, or deployment success.

## Proof Plan

| Area | Input and expected result | Proof |
|---|---|---|
| Activity identity | Same-name Applications with absent/conflicting provenance or ambiguous status must not inherit another source's success | Deterministic map activity fixtures; preserve original result and expose omissions |
| Request cost | Repeated scoped MCP calls execute one ConfigHub command per accepted call and no standalone cluster runner calls; invalid scope executes none | MCP request-count contract tests |
| Delivery reads | Space and time window preserved; three ConfigHub commands per collection; malformed/absent evidence stays partial | Delivery collector contract tests |
| Freshness | Old successful status remains stale/WATCH rather than PASS | Fixed-clock live-status fixtures |
| Context | Child commands inherit intended ConfigHub context without changing kube context | Subprocess/environment contract and non-production smoke |
| Five modes | Standalone/plugin evidence parity, MCP round trip, watch/bot events with read-only auth | Existing parity/bot/watch contracts plus live smoke |
| Distribution | Packaged standalone and plugin entry points, correct version, runnable container | Archive inspection and container smoke |

Examples: `examples/mcp-gateway/`, `examples/live-delivery-observability/`, and
`examples/bot/`. Add negative cases and exact reproduction commands alongside
the tests. Fleet identity proof uses isolated fixtures, not an all-cluster sweep.

## Recorded Validation

- Full `go test ./...`, build, read-only policy, and CLI-guide parity passed.
  The full suite passed again after the MCP namespace fix.
- The final local suite also passed with CI-style atomic coverage enabled.
- Focused identity and scoped-read tests passed twice, then again after docs.
- Local kind smoke: eight inventory resources match between standalone and
  plugin mode; watch and bot each emit eight `resource.discovered` observations.
- Live MCP stdio round trip returns the same eight namespace-scoped resources.
- Isolated kind v1.35.0 bot Pod completes with `runAsNonRoot`, a read-only root
  filesystem, and observation events. Its ServiceAccount can list Deployments
  and cannot patch them. The image uses the base account's numeric UID 65532.
- GoReleaser v2.18.1 snapshot builds all six OS/architecture archives; checksums
  pass. Linux/macOS archives contain `main`, `cub-scout`, and the kubectl entry
  point; Windows archives contain the two standalone executables. Extracted
  macOS standalone/plugin binaries and the local Linux container execute.
  Snapshot version labels are not published release tags.
- CI's first run found an existing demo-worker test starting a login shell in
  its `script -c` mock. The mock now uses a non-login shell to preserve its
  isolated PATH and avoid accidentally selecting a real `cub` binary.
- `cub v0.4.4` exposes all three required Resource/type command surfaces.
  Authenticated ConfigHub reads are unverified because the local token expired.
  Recorded collector/MCP fixtures cover errors, freshness, and context behavior.
- Read counts are command invocations: one `cub` command per accepted Resource
  tool call; three per delivery collection. The host may paginate. There is no
  automatic shared cache or global API-rate guarantee in this release.
- Application correlation requires explicit Space ID metadata. Source URL or
  name conventions alone are insufficient. Status writeback lacks full
  cluster/namespace/operation identity, so joined data is supporting context,
  not proof that a particular delivery operation completed.
