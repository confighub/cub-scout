# v2.10.0 Explorer Integration (Unreleased)

This is a working release note, not a published release. The latest published
version is v2.9.0. Tracking: #519 (explorer), #505 (provenance), #502 (delivery).

## Implemented Scope

- #522 merged: opt-in exact-object `explain --bounded` with explicit
  `--api-version`, `--kube-context`, and namespace for namespaced resources.
  A cold read uses at most one discovery document and one object GET.
- CLI/plugin, MCP, and the existing TUI picker use the same evidence model.
  MCP/TUI reuse up to 16 observations for less than 15 seconds; explicit refresh
  invalidates earlier evidence. Context and selected credential-configuration
  changes invalidate reuse. No cross-process or fleet-wide cache is claimed.
- The follow-up origin slice under #505 parses `confighub.com/origin` from
  the existing object read: `configHubOrigin` reports observed source space/unit
  IDs and slugs plus optional integer revision. Missing, malformed, duplicate,
  unsupported, and legacy-conflicting metadata have explicit omissions.
- Both slices have README user questions, contract documentation, and the
  [bounded resource example](../../examples/bounded-resource-read/).

## Boundaries

Origin metadata is not verified source, delivery success, application health,
controller ownership, or release/target/component/variant membership. It cannot
bind a ConfigHub Target to a Kubernetes context. Bounded checks deliberately
omit controller-source, related-pod/event, and desired/live comparison reads.

The companion evidence panel is not implemented. Existing standalone TUI
behavior remains available; its normal inventory cost is not the bounded
operation's two-request budget. Watch/bot, rich trace/explain, receipts, and
connected Resource joins do not gain origin support in this slice.

## Release Gates Still Open

- Final scope decision for the remaining #502/#505 work; no umbrella closure

- Final-head CI, release archives, version/plugin checks, container pull proof,
