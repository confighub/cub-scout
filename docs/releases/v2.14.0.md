# v2.14.0 — Bounded investigation and conservative collection evidence

**Draft — unreleased.** Published baseline is v2.13.3; see its notes and those
of v2.13.2 for the candidate work the published builds already carry. This draft records implemented portions of the
integrated 2.14 candidate. It does not narrow the adopted P4 scope or certify a release.
[Readiness](v2.14-readiness.md), [the execution plan](../roadmap-3.0-execution.md)
and [#645](https://github.com/confighub/cub-scout/issues/645) govern acceptance.

## Implemented candidate changes

- Watch and bot accept strict explicit Kubernetes context selection. One captured
  config feeds inventory, scanner, receipt and optional informer clients; missing
  or blank selections refuse before sink creation, without ambient fallback.
  Defaults and event schemas are unchanged. This selects scope without claiming
  verified cluster identity, total costs or fresh informer observations.

- Opt-in map cluster identity binds inventory and one bounded kube-system
  Namespace read to the same selected config. The separate identity report
  preserves partial/unavailable collection separately from identity verification.
  Context labels do not establish stable identity. Cost fields cover the identity
  reader, not total command cost. CLI/MCP and the loaded TUI identity view share
  this model; unsupported TUI actions are guarded when identity binding is active.
- Opt-in map resource rows retain observed object-instance references and canonical
  merge keys, or explicit identity omissions. Missing UID/scope/type and denied or
  wrong cluster evidence never fall back to names. CLI/MCP and the loaded TUI
  share this evidence without extra reads; legacy/default output is unchanged.
- Watch/bot collection omissions emit `collection.partial` diagnostics. Failed
  resource LISTs preserve a private diff baseline, preventing false deletions or
  rediscovery during denial/recovery. The diagnostic has no object receipt or
  inferred owner. This is inventory coverage, not proof of scanner completeness.
- Recorded ownership pagination limits returned rows while preserving full-scope
  counts and owner totals. Canonical cursors bind exact recording bytes, filters
  and page size. CLI, MCP and loaded TUI pages share the deterministic model.
  The separate page schema preserves default full/summary contracts. This is a
  record limit, not a byte/token budget, input-work limit or savings measurement.
  A separate opt-in report JSON byte budget refuses oversized report data without
  clipping evidence; it excludes display/newline, MCP duplication/protocol/transport,
  input work, tokens and agent cost. A refused TUI page preserves its current state.
- Crossplane lineage refuses ambiguous, foreign and self-parent joins. Known-group
  owner references preserve exact version/type/name and check a supplied UID;
  missing/replaced evidence stays partial with explicit reasons. Label-only joins
  still do not establish UID identity. This correction does not graduate Crossplane
  or implement the complete v2 condition/operation/coverage model.

- Composition trees retain same-name children of a different full reference and
  separate colliding root API references and present/partial observations.
  Unambiguous JSON keys remain unchanged; collision keys are deterministic and
  opaque. This is presentation grouping, not verified cluster/object UID identity.

- kro owner-reference lineage refuses wrong-type/version/namespace, ambiguous,
  self and stale-UID candidates. Unobserved parent namespace stays unknown with
  explicit omission evidence. Metadata-only definition lookup remains separate.
