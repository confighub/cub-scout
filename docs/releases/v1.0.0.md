# v1.0.0 Release Notes

**cub-scout is stable.**

After 19 releases of iterative development, testing, and real-world usage, cub-scout v1.0.0 marks the first stable release with locked CLI and schema contracts.

---

## What You Can Do Now

### Explore Your Cluster

```bash
cub-scout map              # Interactive TUI dashboard
cub-scout tree ownership   # See resources grouped by GitOps owner
cub-scout map list         # Scriptable resource listing
```

### Trace Any Resource to Git

```bash
cub-scout trace deploy/api-server -n production
```

Works with Flux, ArgoCD, Helm — auto-detects the GitOps tool.

### Find Problems Fast

```bash
cub-scout scan                    # 46 misconfiguration patterns
cub-scout scan --lifecycle-hazards # Helm hook risks under ArgoCD
cub-scout gitops status           # Pipeline health check
```

### Automate Everything

```bash
cub-scout map list --json | jq    # JSON output for tooling
cub-scout graph export            # Resource graph as JSON
cub-scout snapshot --relations    # Full state export (GSF format)
```

## Offline-First, Connected Optional

**Standalone:** Works offline, no signup, no network required. Everything in the CLI contract works standalone.

**Connected:** Optional ConfigHub integration for fleet features. Run `cub auth login` to enable.

| Feature | Standalone | Connected |
|---------|:----------:|:---------:|
| Map, tree, trace, scan | ✓ | ✓ |
| Deterministic JSON output | ✓ | ✓ |
| Debug bundles | ✓ | ✓ |
| Fleet queries | — | ✓ |
| Import to ConfigHub | — | ✓ |

## Stability Guarantees

### CLI Contract v1.0

- **Flag names are stable** — existing flags will not be renamed or removed
- **JSON schema is stable** — fields will not be removed, only added
- **Exit codes are stable** — 0 = success, 1 = error
- **Query syntax is stable** — existing operators work as documented

### Sealed Schemas

- `attribution-graph.v1`
- `attribution-report.v1`

### Breaking Change Policy

Breaking changes require a new major version (v2.0+). We define breaking as:
- Removing a command or flag
- Changing exit code semantics
- Removing JSON fields
- Changing query syntax in incompatible ways

## Maps & Trees

cub-scout provides multiple hierarchical views:

```bash
cub-scout tree runtime      # Deployment → ReplicaSet → Pod
cub-scout tree ownership    # Resources by GitOps owner
cub-scout tree git          # Git repository structure
cub-scout tree composition  # Crossplane XR → composed resources
```
