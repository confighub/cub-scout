# v2.12.2 - Clear cub Upgrade Guidance and Exact Unit-Event Outcomes

**Published: 2026-09-26.** Tag `v2.12.2` at `35a41cf`. Previous release: v2.12.1.
A patch release: no new commands, flags or JSON fields.

## User Value

ConfigHub 0.6 changed its API, and `cub auth status` now refuses a `cub` whose
minor version is older than its server's. Two fixes make cub-scout say what is
actually wrong:

- **cub older than its server** ([#608](https://github.com/confighub/cub-scout/issues/608),
  #610). Connected commands now refuse with "`cub` is older than the ConfigHub
  server; run `cub upgrade`", followed by cub's own message, instead of
  reporting an authentication failure. `status` no longer prints
  "auth expired / Run: cub auth login" for a session that is valid.
- **Unit-event outcomes** (#611, part of
  [#561](https://github.com/confighub/cub-scout/issues/561)). `map activity` and
  `doctor --with-confighub` classify ConfigHub unit events by ConfigHub's exact
  status values. `Aborted` and `Canceled` are now `inconclusive` (they were
  `normal`), `Submitted` is `pending` (it was `normal`), and no unrecognised
  value is ever `success` (an aborted action whose function invocation had
  completed was reported as `success`).

Checked live against a hosted ConfigHub 0.6.5 server with cub 0.5.7, which cub
refuses. The v2.12.1 `status` printed:

```
ConfigHub:  ● Connected (auth expired)
            ⚠ Token expired or invalid
            Run: cub auth login
```

This release prints:

```
ConfigHub:  ● Connected
            ⚠ ConfigHub reads unavailable: `cub` is older than the ConfigHub server; run `cub upgrade`: cub v0.5.7 is too old for server v0.6.5: ...
```

with `auth_valid: true` and `confighub_reads: false` in `status --json`. With
cub 0.6.2 against the same server, reads are available.

Also on `main` since v2.12.1, documentation and examples only:

- #589: the apptique example approves Spaces with `cub variant approve`,
  because cub 0.6 removed `cub unit approve`.
- #593: cub-scout refuses `cub unit approve` like the other removed `cub`
  subcommands (no cub-scout code path called it), and the read-first docs
  record what cub 0.6 changed.
- #586, #587: published v2.12.1 checks and the image-verification guide.
- #592, #598, #609: the roadmap's 3.0 direction, Path to 3.0 and ConfigHub
  Attestations follow-up.

## cub Compatibility

- cub 0.6 removed `cub unit approve` and the `ApprovedBy` and
  `UnapprovedUnitCount` fields. No cub-scout code path used them.
- Keep cub at or above the ConfigHub server's minor version. A cub newer than
  its server only warns, and connected reads proceed.

## Limits

- Recognising cub's refusal depends on the text of cub's message, because cub
  offers no machine-readable form. An unrecognised message keeps the previous
  behaviour: the "did not report an authenticated session" refusal.
- `Aborted` and `Canceled` unit events are `inconclusive`, not `failed`, so
  `doctor` does not promote them to issues.
- #561's other items remain open: connected-history rows in the map TUI,
  unit-event rows in the Markdown trace, related-reference deduplication and
  remaining non-OCI slug joins.
- v2.12.1's limits still apply.
