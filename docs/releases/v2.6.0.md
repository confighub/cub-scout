# v2.6.0 Release Notes — First-Class Controller Evidence

> **Status:** Published on 2026-06-24.
> **Previous release:** [`v2.5.0`](v2.5.0.md) — cross-tool rendered-set digests and receipt chain walking.

**Theme:** *make more controllers first-class evidence sources, and compare rendered object sets directly.*

This release is additive. It does not change cub-scout's read-only boundary, CLI exit-code contract, or existing JSON fields. New owners, fields, docs, and receipt surfaces are additive.

## Highlights

### Sveltos is first-class

cub-scout now recognizes Sveltos as a built-in owner and controller family.

Supported evidence includes:

- Sveltos API groups:
  - `config.projectsveltos.io/v1beta1`
  - `lib.projectsveltos.io/v1beta1`
- `ClusterProfile` and `Profile` deployment intent
- `EventSource` / `EventTrigger` event-driven behavior
- `ClusterHealthCheck` notification/health configuration
- deployed-resource annotations such as:
  - `projectsveltos.io/owner-kind`
  - `projectsveltos.io/owner-name`
  - `projectsveltos.io/reference-kind`
  - `projectsveltos.io/reference-name`
  - `projectsveltos.io/reference-namespace`

Sveltos now appears naturally in ownership detection, map views, doctor summaries, trace output, activity timelines, deployer/status views, TUI pipeline and trace views, docs, and AI skill routing.

Main guide: [`docs/howto/observe-sveltos.md`](../howto/observe-sveltos.md)

### Modelplane is first-class

cub-scout now recognizes Modelplane as a built-in owner and controller family.

Supported evidence includes:

- `modelplane.ai/v1alpha1` resources:
  - `InferenceGateway`
  - `InferenceClass`
  - `InferenceCluster`
  - `ModelDeployment`
  - `ModelService`
  - `ModelEndpoint`
  - `ModelCache`
  - `ModelReplica`
- `infrastructure.modelplane.ai/v1alpha1` resources:
  - `EKSCluster`
  - `GKECluster`
  - `ServingStack`
- explicit Modelplane ownership labels such as:
  - `modelplane.ai/deployment`
  - `modelplane.ai/modelcache`
  - `modelplane.ai/serving`
  - `modelplane.ai/cluster`

Broad scheduling/placement labels are not treated as ownership proof. cub-scout requires Modelplane API objects, explicit ownership labels, owner references, or status evidence.

Main guide: [`docs/howto/observe-modelplane.md`](../howto/observe-modelplane.md)

### Trace, doctor, activity, and TUI coverage

Sveltos and Modelplane are not custom-detector side paths. They are wired into the normal surfaces:

- `map list --owner Sveltos`
- `map list --owner Modelplane`
- `trace <kind>/<name>`
- `doctor --format json`
- `map activity --owner Sveltos`
- `map activity --owner Modelplane`
- `map deployers`
- `gitops status`
- TUI pipeline and trace views

`trace` stays evidence-shaped:

- Sveltos trace shows the deployed resource, referenced `ConfigMap`/`Secret` metadata, and `ClusterProfile`/`Profile` owner when readable.
- Modelplane trace shows Modelplane parent links and composed children where labels/owner refs/status expose them.
- `trace -d` does not fabricate desired-state Git diffs for Sveltos or Modelplane when only observed controller evidence is available.

### Object-set diff and receipt support

`compare object-set --dry-from` adds a direct rendered-object-set comparison path, with an `ObjectSetDiffReceipt` evidence shape for set-level install assertions.

This complements the v2.5 digest and receipt-chain work:

- compare a rendered object set against live state
- preserve deterministic object-set identity
- report missing, changed, and extra objects without requiring connected mode
- keep the witness read-only

### Workload convergence receipt hardening

`workloads-converged` receipts now use safer progress-clock handling:

- records `generation` / `observedGeneration`
- records progress age and progress clock source when known
- avoids turning stale `observedGeneration` into a fabricated timeout
- keeps `InProgress` as WATCH when there is no reliable progress clock

This prevents false BLOCK verdicts when Kubernetes status has not caught up to the current generation.
