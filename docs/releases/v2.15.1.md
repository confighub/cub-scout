# v2.15.1 — Answers an agent can take at face value

**Published 2026-11-13.** [Release and assets](https://github.com/confighub/cub-scout/releases/tag/v2.15.1)
at source `9fa4f306039317a915aa1ebcbd210eb17f9af522`. The
[tagged tests and packaging run](https://github.com/confighub/cub-scout/actions/runs/43479249018)
passed on its second attempt; see [Publication checks](#publication-checks).
The release before it is [v2.15.0](v2.15.0.md).

A correction release, and more than a patch in two places: read
[Behaviour changes to expect](#behaviour-changes-to-expect) before upgrading
if you consume `compare source-truth` or `trace` JSON, or run Flux older than
2.6.

Everything here came from recording cub-scout's answers on real Flux, Argo CD
and Sveltos clusters in CI and reading them as an agent would: a reader that
takes each word at face value. The rules that came out of it are in
[Agentic GitOps observability](../reference/agentic-gitops-observability.md#lessons-from-real-clusters--2026-11-13).

## Fixed

- **`compare source-truth` works on a cluster attached with `cub cluster up`**
  ([#906](https://github.com/confighub/cub-scout/pull/906), refs
  [#882](https://github.com/confighub/cub-scout/issues/882)). Workloads
  delivered that way carry a `confighub.com/origin` annotation and none of the
  older `UnitSlug` / `SpaceName` metadata. Under `confighub-oci-flux` and
  `confighub-oci-argo` the command answered "not ConfigHub-managed" and BLOCK.
  It now reads the unit and space the annotation names.
- **Flux `ExternalArtifact` and `ArtifactGenerator` are found**
  ([#908](https://github.com/confighub/cub-scout/pull/908)). Both were looked
  for under the Flux Operator's API group, which does not serve them, so
  `map`, `doctor` and `gitops status` have never listed either kind. They are
  read as `externalartifacts.source.toolkit.fluxcd.io/v1` and
  `artifactgenerators.source.extensions.fluxcd.io/v1beta1`.
- **Flux `OCIRepository` and `Bucket` are read as `v1`**
  ([#908](https://github.com/confighub/cub-scout/pull/908)). Seven places read
  `v1beta2`, which Flux 2.10 does not serve. A healthy chain printed
  `timing unavailable ... not found`, and the TUI's source list showed no OCI
  sources.
- **A freshness race in the live-status check**
  ([#904](https://github.com/confighub/cub-scout/pull/904)). A status recorded
  between the start of the command and the read of the Release was called
  `unknown`.

## New

- **The live-status cluster check compares health, and names Sveltos**
  ([#904](https://github.com/confighub/cub-scout/pull/904), refs
  [#887](https://github.com/confighub/cub-scout/issues/887)).
  `gitops status --with-confighub` adds `clusterCheck.health`: the recorded
  health beside the Deployments, StatefulSets and DaemonSets the compared
  controllers list. A Sveltos ClusterProfile is named and never compared,
  because Sveltos reports no digest for what it applied.
- **`surfaces.confighub.object_revision`** in `compare source-truth`: the unit
  revision the object itself names.
- **`trace --artifacts` says "not applicable"** for a source with no object of
  its own, such as an Argo CD Application's Git or OCI source
  ([#911](https://github.com/confighub/cub-scout/pull/911)).
- **`explain --bounded` without a context prints the flag to add.**
- **A smaller MCP catalog, held to a declared size**
  ([#910](https://github.com/confighub/cub-scout/pull/910)). The 8 standalone
  tools went from 17,465 to 15,120 bytes as `tools/list` returns them, and all
  21 from 33,947 to 31,126. No tool, parameter or schema changed.

## Behaviour changes to expect

- **`compare source-truth`, ConfigHub OCI strategies: PASS means more, and
  some answers that were PASS are now WATCH**
  ([#909](https://github.com/confighub/cub-scout/pull/909)). PASS used to be
  given whenever the three surfaces were present, with nothing compared
  between them. It now requires the unit revision the object names to be the
  head revision read. An object with only the older `UnitSlug` / `SpaceName`
  metadata names no revision and gets WATCH with
  `proof_gaps: ["confighub.object_revision"]`. Two more gaps exist:
  `confighub.object_revision_differs_from_head` and
  `controller.source_names_another_space`. A consumer that pairs fixtures
  with `test/fixtures/source-truth` should add `object_revision` to the
  inputs it expects PASS from. The digest is still not compared.
- **A blocked `compare source-truth` answer** points at `collection_errors`
  for the reason; `safe_next_action` no longer says to verify the `cub`
  login.
- **`trace` JSON under Argo CD:** a plain OCI source has `kind: "OCI"`. It was
  `"OCIRepository"`, a Flux kind that names no object in that cluster.
- **Wording.** Hints, the `map orphans` header and its help say that no owner
  marker was recognised. They no longer say resources "lack GitOps ownership"
  or are "not managed". `Native` has always meant the first; it does not
  prove the second.
- **Flux older than 2.6.** `OCIRepository` and `Bucket` are read as `v1`. The
  timing read and the TUI source list fall back to `v1beta2`; other reads of
  those two kinds do not.

## Limits

- `compare source-truth` compares no digest under the ConfigHub OCI
  strategies.
- `trace` JSON still carries `"error": "resource not managed by ..."` for a
  resource with no recognised owner marker, and the `orphans` command keeps
  its name.
- The health comparison reads Deployments, StatefulSets and DaemonSets only,
  and counts a workload scaled to zero as ready.

## What was and was not verified

- **On real clusters, in CI.** The `live-status` lane makes a kind cluster
  with `cub cluster up` for Flux, Argo CD and Sveltos against a disposable
  ConfigHub v0.10.11. On Flux and Argo CD it requires `compare source-truth`
  to return PASS with no proof gap for the delivered workload, and the
  recorded health to agree with the workloads. On Flux it fails if cub-scout
  reads one of eight Flux kinds in a version the cluster does not serve. On
  Sveltos it requires every check to be `not-observable` with the
  ClusterProfile named.
- **Independent review.** #904, #906 and #909 were each read by a reviewer
  that did not write them, after CI was green. Each review found faults that
  were fixed before merge.
- **Not seen on a real cluster:** a disagreement between a recorded status and
  the cluster; a StatefulSet or DaemonSet in the health comparison; an
  `ExternalArtifact` or `ArtifactGenerator` object; a Flux older than 2.6.
- **Not measured:** whether the shorter MCP catalog, or any change here,
  alters which tool an agent picks or what it costs. No paid eval run was
  made for this release; the eval cases for #904, #906, #909 and #910 are
  waived for that reason.
- **Hosted ConfigHub** was not used for any of this.

## Publication checks

Made on 2026-11-13 against the published artifacts:

- **The Release run failed once before it published anything.** Its test step
  hit a timing race in `TestBoundedExecAuthHungHelperCancellationReapsProcessGroup`,
  which read a helper's PID file before the PID was written. The same commit
  had passed `main` CI (run 43476812506). The job was re-run and passed; the
  race is fixed separately in
  [#913](https://github.com/confighub/cub-scout/pull/913), which is not part
  of this release.
- Six archives and `checksums.txt`, named as the install guide names them;
  `shasum -a 256 -c checksums.txt` reports all six OK.
- `cub-scout version` prints `2.15.1` and `ConfigHub SDK v0.10.11` from the
  macOS arm64 binary, the macOS amd64 binary under `arch -x86_64`, and the
  Linux arm64 and amd64 binaries in `busybox:stable` containers.
- The published macOS arm64 binary's `tools/list` is 8 tools and 15,120
  bytes with no cluster and no ConfigHub login, as the notes say.
- `cub plugin install confighub/cub-scout@v2.15.1` with a private `HOME` and
  `CUB_CONFIG` (cub v0.9.0) installs it, and `cub scout version` prints
  `2.15.1`.
- `proxy.golang.org` serves `v2.15.1` for `github.com/confighub/cub-scout/v2`
  at the tagged commit, and as `@latest`.
- The Homebrew formula in `confighub/homebrew-tap` names the `v2.15.1` source
  archive, and its `sha256` matches that archive as downloaded.
- The image `ghcr.io/confighub/cub-scout:v2.15.1` (also `:latest`) was pushed
  with digest
  `sha256:63ccb4455f465d2e7751b65c06ff2fd5c15fd956f00bebc0c786f693960ba8d6`,
  read from the workflow log.

Not done: `brew install` (it changes the machine), running the Windows
binaries, and an anonymous pull of the image (denied,
[#520](https://github.com/confighub/cub-scout/issues/520)). No connected
command was run with the published binary against a ConfigHub server.
